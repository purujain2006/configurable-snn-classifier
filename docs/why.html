Why this project exists

Every part of this project answers a problem, and most answers created the next problem. This page tells that story from the beginning, with no background assumed: why neural networks cost so much energy, why a brain does not, what a chip built like a brain changes, and what each change costs.

0.1The story in one picture

Read it top to bottom. Each step is a problem, the idea that answered it, and the new problem that idea raised. Each row links to the section below that explains it.

  1. Problem Some tasks, like recognizing a gesture, have no rules anyone could write down. Idea Neural networks, which learn from examples.
  2. Problem Running them costs a lot of energy, mostly spent moving numbers between memory and processor. Idea Look at how brains avoid that.
  3. Problem Brains keep memory where the computing happens, and neurons only talk when they have something to say. Idea Build chips the same way: neuromorphic computers such as HiAER-Spike.
  4. Problem Such a chip only runs networks whose neurons talk in spikes. Idea Spiking neural networks.
  5. Problem Spiking networks round every number and cannot be trained the usual way, so they lose accuracy. Idea Surrogate gradients, and training with spikes from the start.
  6. Problem A real chip has fixed limits: connection tables, 16-bit numbers, a cheap leak. Networks trained the usual way break them. Idea Train with the chip's own rules, and check every result on an exact simulator of the chip.
  7. Problem A network has about thirty settings and trillions of combinations, and no rule says which will fit and score well. Idea An automated search.
  8. Problem A search can fool itself with lucky or memorized results. Idea Held-out people, a test set used once, and retraining the finalists.
  9. Where it stands Networks that fit the chip now beat the published result. Overfitting, and how much work the networks do, are the open problems.

0.2Computers that learn from examples

An ordinary program is a list of rules a person wrote. That works for adding up a bill, and fails for recognizing a hand wave: nobody can write down which pixels make a wave, because every person, angle and lighting gives different pixels. A neural network takes the other route. It is a large calculation with millions of adjustable numbers, called weights, and it is shown thousands of labeled examples. After each example its weights are nudged so its answer gets a little closer to the right one, until the network gets most examples right on its own. That nudging is called training.

The calculation itself is simple and repetitive: multiply each input by a weight, add the results, pass the sum on to the next layer, and repeat. A network that recognizes gestures does tens of millions of these multiply-and-add steps for every clip it looks at. Page A builds one up from a single neuron.

The new problem

Tens of millions of operations per answer, for every answer, adds up to a lot of energy. The largest data centers that run neural networks draw as much power as a small town, and a battery-powered sensor cannot run a large network for long.

0.3Where the energy goes: the von Neumann bottleneck

Almost every computer, from a phone to a graphics card, follows a design described by John von Neumann in 1945: memory holds the numbers, a separate processor does the arithmetic, and a connection between them, the bus, carries every number back and forth. For a neural network, the weights live in memory, so every multiply first needs its weight fetched across that connection.

The surprise is how the cost splits. Doing the multiplication is cheap. Fetching the number is not: reading one 32-bit number from main memory takes roughly 170 times the energy of multiplying two 32-bit numbers. Most of a network's energy therefore goes into moving weights around. This limit is called the von Neumann bottleneck, after a 1977 lecture by John Backus that named it.

ANIMATION One neuron's worth of work on an ordinary computer Each weight travels from memory to the processor before it can be used. The meters add up the energy spent moving numbers and the energy spent multiplying and adding them.

Each packet is one weight. Moving it from main memory costs about 640 picojoules (a picojoule is a millionth of a millionth of a joule); multiplying and adding it costs about 4.6. After a few weights the "moving" meter dwarfs the "computing" one, whatever the network does with the numbers.

The new problem

The cost sits in the trip between memory and processor, so a faster processor leaves it untouched. Fixing it means changing where the numbers live.

0.4How a brain avoids it, and chips that copy the brain

A brain has about 86 billion neurons and runs on roughly 20 watts. Two habits make that possible.

  • Memory sits where the computing happens. A brain's "weights" are the strengths of its synapses, the junctions between neurons, and they are part of the neurons that use them. Nothing is fetched from a distant memory.
  • Neurons only talk when they have something to say. A neuron sends a brief electrical pulse, a spike, only when its input pushes it past a threshold. Most neurons are silent most of the time, and a silent neuron costs almost nothing.

A neuromorphic computer is a chip built on the same two habits. Its memory is split into many small pieces, each sitting next to the circuits that use it, and it does work only when a spike arrives. HiAER-Spike is one, built at UC San Diego. Its name stands for Hierarchical Address-Event Routing: when a neuron fires, the chip sends a tiny message holding only that neuron's address, and a hierarchy of routers delivers it to every neuron it connects to, which then add that connection's weight to their own running total. It runs on FPGAs, chips whose circuits can be rewired after they are made, which lets a new design run today without the years and cost of manufacturing a custom chip.

The new problem

A chip like this only runs one kind of network: one whose neurons communicate in spikes. The networks that power today's software pass exact numbers between neurons on every step, so they cannot run on it as they are.

0.5Spiking neural networks

A spiking neural network is a neural network rebuilt around spikes. Each neuron keeps a running total of its input, called its membrane potential. When the total passes a threshold, the neuron sends a spike and starts again; between inputs, the total slowly leaks away, so old input fades. The network runs in small time steps, and its answer is read from which output neuron fired most.

Because a spike either happens or does not, a connection only does work in the steps when its neuron fires. A layer where few neurons fire does little work, which is the source of the energy saving. Page A shows this neuron working, and A.9 counts the work it saves.

The new problem

Spikes are a coarse language. A number like 0.37 has to be spread out as a spike on about 37% of the steps, so every answer is rounded, and the rounding compounds through the layers. Worse, the usual training method needs the slope of every step of the calculation, and a spike, which jumps from 0 to 1, has no useful slope. For years spiking networks lagged well behind ordinary ones in accuracy.

0.6Getting accuracy back

Two ideas closed much of that gap. The first is the surrogate gradient, which became the standard method around 2018 and 2019: during training, the spike's missing slope is replaced by the slope of a smooth curve shaped like it, while the network itself still fires real spikes. That lets spiking networks learn with the same method ordinary networks use (A.10). The second is to train the network as a spiking network from the very beginning, instead of training an ordinary network and converting it, so its weights grow used to the rounding (A.8).

The new problem

A network trained this way still assumes ideal arithmetic: any number of connections per neuron, numbers with many decimal places, any leak. A real chip offers none of that.

0.7The chip's rules, and why they exist

Every limit on HiAER-Spike buys something: smaller circuits, more neurons per chip, or less energy per spike.

connection tables
Each neuron's incoming connections live in a table of fixed size in the chip's memory, which keeps every lookup fast and the circuit simple. So a neuron can receive at most 8,159 connections, its fan-in (G.3).
16-bit whole numbers
The chip stores one weight per connection, billions of them, so each is a 16-bit whole number instead of a longer decimal one. That halves the memory of the 32-bit numbers networks usually train with and keeps the adders small, at the cost of rounding every weight (G.4).
a leak by halving
Dividing by a power of two is a bit shift, nearly free in hardware, while general division is costly. So τ (tau), the number that sets how fast a neuron's total leaks away, can only be 2, 4, 8, 16 and so on (F.3).
no normalization step
Batch normalization, a training aid that rescales each layer, would need extra arithmetic on every step. After training it is just a fixed scale and shift, so it can be merged into the weights and thresholds instead (G.5).
16,000 input lines
Input arrives from outside on a fixed number of lines, called axons, so camera frames have to be shrunk to fit (B.2).

A network trained the usual way breaks these rules, and converting it afterwards loses accuracy or does not fit at all. This project's answer is to train with the chip's rules built in: the chip's exact neuron, integer weights, a power-of-two leak, and a check of every network's size before it is trained. When training ends, the network is exported, written out in the chip's own format of neuron tables and integer weights, and then run on a simulator: a program that computes exactly what the chip would, spike for spike. The simulator is used because it gives the chip's answers on any computer, quickly and repeatably, and because the current build of the physical chip still mishandles the leak of negative potentials.

The new problem

Now there are many choices, and each one changes both accuracy and whether the network fits: how many layers, how wide, how each layer shrinks the picture, how the neurons leak, how training runs. About thirty in all.

0.8Too many choices: the search

The numbers a network learns during training are its weights. The choices made before training, which training cannot change, are called hyperparameters (often called settings on this site): the number of layers, the width of each layer, the learning rate and so on. Thirty of them give trillions of combinations, each needs a full training run to score, and they interact, so no rule of thumb picks a good set.

A hyperparameter search tries combinations automatically. Each attempt is a trial: build the network, check it fits the chip, train it, export it, score it on the simulator. This search starts with a balanced set of trials that tests every option fairly, then uses what scored well to choose what to try next, and stops trials that are clearly losing so the computer's time goes to promising ones. Page C follows a trial through every stage and then the search as a whole.

The new problem

Out of hundreds of trials, the best score is partly luck, and a network can score well by memorizing the examples it trained on rather than learning the gesture.

0.9Measuring honestly

The data is split three ways. The network trains on one part. Trials are compared on a second part, the validation set, held back from training, so memorizing does not help. The third part, the test set, is used once at the end, because a set that is used again and again to choose ends up flattering the choice. Both held-back sets come from people the network never trained on, since the real question is whether it recognizes gestures from strangers. And the best few configurations are trained again with fresh random starts before a winner is named, to separate good settings from good luck. Page B covers the split and how much one score can move by chance.

0.10Where the story stands

On the gesture task, the best network chosen this way recognizes 85.4% of the test clips on the chip simulator, against 68.75% in the HiAER-Spike paper, and it fits every limit of the chip. So obeying the chip's rules has not cost accuracy.

Two problems are open, and they close the loop back to the start of this page. The networks memorize: they get 98 to 100% of their training clips right and about 80% of new people's. And the accurate networks do more work than a conventional network of the same shape, because they use long clips and busy neurons, so the energy saving that motivated all of this is not yet realized. Page H has the numbers and the next experiments.

In short

Neural networks spend most of their energy moving numbers between memory and processor. Brains avoid that by keeping memory with the neurons and sending spikes only when needed, and neuromorphic chips such as HiAER-Spike copy them. Running on such a chip requires spiking networks, which lose accuracy and are hard to train; surrogate gradients and training with spikes from the start recover much of it. The chip's limits require training with its own rules and checking on an exact simulator, the many choices require an automated search, and honest measurement requires held-out people and a test set used once.
