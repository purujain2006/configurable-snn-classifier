Training

This page follows one gesture recording through the pipeline: how the event stream becomes network input within the axon budget of section 1.3, how spike counts become a prediction, how the layer delay from section 2.1 is accounted for, and what the run reports at the end.

5.1From recording to tensor

Each DVS128 Gesture recording is a list of events of the form (x, y, polarity, timestamp) at microsecond resolution. The SpikingJelly library converts a recording into frames, and the code requests a fixed number of frames per clip.

frames_number
Set to T, so every clip yields the same number of frames regardless of its duration.
split_by
Set to "number", so each frame covers an equal count of events rather than an equal span of time. Fast motion produces short frames and slow motion produces long ones.
rasterization
Events within a frame are accumulated per pixel and per polarity channel.
result
One tensor of shape (T, 2, 128, 128) per clip.

Three settings in build_dataloaders affect how comparable the reported numbers are.

  • The 15% validation split is drawn after torch.manual_seed(1), so every run and every search trial is scored against the same held-out clips.
  • drop_last is enabled on the training loader only. On validation it would discard up to N−1 clips and bias every accuracy figure.
  • num_workers is 0. Each search trial already runs in its own process, and nested worker processes oversubscribe the CPUs and fail on Windows.

Three supporting functions exist because of failures encountered while running searches.

warmup_dataset_cache()
Builds the frame cache for every value of T before any parallel trial starts, since two trials building the same cache directory can corrupt it. A directory missing class folders counts as incomplete rather than usable.
_quiet_with_heartbeat
Suppresses the library's per-file progress output and prints one line every twenty seconds. If the operation fails, the full log is restored.
validate_data_dir()
Reports the expected directory layout up front, so a missing dataset does not surface later as a file error raised from inside the library.

5.2Resizing and binarizing the input

Observation

A 128×128 sensor with two polarity channels needs 32,768 input axons. The chip provides 16,383. The native resolution cannot be presented at all. Separately, the network's input layer expects spikes, and a rasterized frame holds event counts.

Consequence

Frames have to be reduced to 64×64 or 32×32 and converted to binary. The choice of how to reduce them matters: averaging a sparse binary frame produces small fractional values that a spiking input cannot represent, and isolated events disappear.

In code

DVSResizeAndBinarize interpolates and then applies > 0, so any non-zero contribution becomes a full spike. The docstring records the effect: no events are lost, and event density per pixel rises as resolution falls.

5.3Reading a prediction from spikes

The final layer holds 11 neurons, one per gesture. Each emits a train of spikes across the run rather than a single number, so the prediction is defined as the firing rate: total spikes divided by T. The highest rate wins.

During training those 11 rates are treated as class scores and passed to a cross-entropy loss, optionally softened by label smoothing. The winning configurations used a smoothing value near 0.15.

5.4Draining the pipeline

Observation

Section 2.1 established that the chip's neuron fires on the potential it carried in from the previous timestep. Each spiking layer therefore holds its output back by one step. When the input ends after T frames, evidence from the final frames is still in transit and has not reached the classifier.

Consequence

Stopping the simulation at T throws away the last frames of every clip, and how many grows with depth. A network measured that way scores lower on chip than it did in training. Nothing in the configuration says why.

In code

forward_over_time() runs the T input frames and then continues for hardware_flush_steps(net) further timesteps with zero input, accumulating output spikes throughout. The total is divided by T rather than by T plus the flush, so rates stay comparable across depths. This matches what the conversion script measures.

5.5The training step

  1. Forward A batch of clips of shape (N, T, 2, H, W) passes through forward_over_time, producing 11 firing rates per clip. Neuron state is reset afterwards so clips do not influence each other.
  2. Loss Cross-entropy between the rates and the true gesture.
  3. Backward Gradients propagate across all T timesteps, through every spike using the surrogate from section 2.5 and through every quantizer using the estimator from section 4.4.
  4. Update Optional gradient clipping, then the optimizer step and any per-batch scheduler step.

Validation accuracy is measured after each epoch and the best weights are retained, so the reported model is the best epoch rather than the last.

Optimizer and schedule

build_optimizer offers Adam, AdamW and SGD. The distinction between the first two matters more here than usual: Adam adds weight decay to the gradient, where it interacts with the adaptive step size, while AdamW applies it separately. Since section 4.3 showed that weight decay controls whether folded weights stay inside the representable range, the search samples different decay ranges for the two optimizers.

Cosine and onecycle deliver most of their benefit late in the run. Section 6.4 relies on that property when deciding how early a trial may be stopped.

5.6What a run reports

run_training() combines the pieces above with the inline schedule from section 4.5.

PhaseWhat happensReported
warm-up About a quarter of the epoch budget in floating point with batch normalization active, so its running statistics become meaningful. Validation accuracy per epoch.
on-grid The best warm-up weights are reloaded, each convolution and batch normalization pair is fused, and the remaining epochs train on folded and quantized weights at half the learning rate. Validation accuracy per epoch, continuing the same curve.
export The batch-norm-free INT16 network is frozen, evaluated once, and audited by deployment_report. hw_val_accuracy, quant_gap, weight_clip_frac, min_threshold, deployable.

In single mode the console prints both accuracies and the gap between them. The checkpoint written to disk holds the trained network, the deployable network, the configuration, the metrics and the per-layer hardware table, so a conversion can proceed without recomputing anything.
