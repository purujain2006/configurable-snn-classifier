Training

How a camera recording becomes training data, how the network's output spikes become a prediction, and what one training run produces.

5.1From recording to training data

Four pieces of software do the work.

PyTorch
The deep-learning library: arrays of numbers (tensors), layers, and automatic gradients.
SpikingJelly
A PyTorch library for spiking networks. Here it supplies the dataset loader, spiking layers, and the reset of neuron state between clips.
hs_api
The HiAER-Spike Python package: the chip simulator and the interface to the FPGA.
DatasetBundle
This tool's description of a dataset: the training and test sets, the image size and the number of classes. Any dataset that provides one can be used.

A DVS128 Gesture recording is a list of events, each an (x, y, polarity, time) record with microsecond timing. SpikingJelly turns each recording into T frames. Every frame holds the same number of events, so fast motion gives short frames and slow motion long ones. Each frame counts the events at every pixel, separately for brightness increases and decreases, giving a tensor of shape (T, 2, 128, 128) per clip.

Training, validation and test

The data is split three ways. Training data fits the weights. Validation data chooses between networks and decides when to stop. Test data is used once at the end, and it is the only number comparable to published results.

The test set comes with the dataset: six people who never appear in training. Validation is four of the remaining 23 people (216 clips), held out entirely, and the same four in every run. Earlier runs drew validation clips at random from all 23 people, so validation shared people with training. The same network then scored 0.92 on validation and 0.83 on test, because validation rewarded recognizing familiar people. That gap motivated holding out whole people, which makes validation look like the test set.

5.2Turning input into spikes

An encoder decides what the network receives at each step. Event recordings already have a time axis. A still image does not, and the choice of rule changes both accuracy and how many spikes the network fires.

CodingWhat it doesFits
levelsRounds each pixel to a whole number from 0 to 2B − 1 and feeds it at every step, on B input lines (below).Still images on the chip. The default for still images.
directFeeds the same pixel values at every step.Still images in software. The chip's input lines carry spikes only, so this coding cannot run on the chip as is.
poissonEach step, fires a pixel with probability equal to its brightness.Still images on the chip. The randomness costs accuracy at small T.
temporalEach pixel fires once; brighter pixels fire earlier.The fewest spikes, and the hardest to train.
passthroughShrinks event frames and turns any nonzero pixel into a spike, or with B bits, into its event count up to 2B − 1.Event cameras, including DVS128 Gesture.

A 128×128 frame with two channels needs 32,768 input axons, and the chip has 16,000, so frames are shrunk first. The search works out its range of sizes from the dataset: from about a quarter of the largest size up to the native size or the largest square that fits in 16,000 axons, whichever is smaller. For DVS128 Gesture that is 24×24 to 88×88 (2 × 88 × 88 = 15,488 axons). A 32×32 color image fits at full size. Shrinking averages neighboring pixels. A lone event then becomes a fraction that no spike can represent, so the passthrough encoder turns any nonzero result into a full spike and no event disappears.

More than one bit per pixel

An input line carries a spike or nothing at each step, which is one bit. A pixel's brightness, or how many events it saw, needs more. With B bits per pixel, each pixel gets B input lines, and line k carries bit k of the value. Its connections carry the weight multiplied by 2k, so the first layer receives exactly w times the value, as in training. The cost is B times the input lines and B times each first-layer neuron's fan-in. Doubling a weight must not overflow 16 bits, so first-layer weights are limited to 32,767 / 2B−1. The search tries 1 to 4 bits for codings that can send them (levels and passthrough).

5.3Reading a prediction

The last layer has one neuron per class (11 for the gestures), and each fires a train of spikes across the clip. The prediction is the class whose neuron fired most. During training, the spike rates act as class scores in a cross-entropy loss. Label smoothing moves a little of the target away from the correct class, which discourages overconfidence.

5.4Letting the last frames arrive

Each spiking layer delays its output by one step (section 2.1). When the input ends after T frames, the effect of the last frames is still on its way to the output. Stopping at T would discard it, and a deeper network would lose more.

So after the T input frames the tool runs one extra step per spiking layer with no input, called flush steps, and counts output spikes throughout. The count is divided by T so scores stay comparable across depths. The simulator check runs the same number of steps.

Follow the last frame through two layers

Take two spiking layers and T input frames. Layer 1 adds frame T to its potential at step T and can fire about it at step T+1, when layer 2 receives that spike; layer 2 can then fire at T+2. Two flush steps let both responses reach the count.

Source: snnsearch/train.py
snnsearch/train.pyforward_over_time
def forward_over_time(net, x, flush_steps: int = None):
    x = x.transpose(0, 1)  # (T, N, C, H, W)
    T = x.shape[0]
    if flush_steps is None:
        flush_steps = hardware_flush_steps(net)
    if getattr(net, "step_mode", "s") == "m":
        if flush_steps > 0:
            pad = torch.zeros_like(x[:1]).expand(flush_steps, *x.shape[1:])
            x = torch.cat([x, pad], dim=0)
        out = net(x).sum(0) / T
    else:
        out_sum = 0.0
        for t in range(T):
            out_sum = out_sum + net(x[t])
        if flush_steps > 0:
            zeros = torch.zeros_like(x[0])
            for _ in range(flush_steps):
                out_sum = out_sum + net(zeros)
        out = out_sum / T
    functional.reset_net(net)
    return out

5.5One training step

  1. Forward. A batch of clips, shape (N, T, C, H, W), goes through the network for T plus flush steps, giving one spike rate per class for each clip. Neuron state is then reset so clips do not affect each other.
  2. Loss. Cross-entropy between the rates and the true classes. The search also tries TET (temporal efficient training, Deng et al., 2022), which averages a cross-entropy computed at every step, so each step learns to classify on its own. The prediction is the rate either way.
  3. Backward. Gradients flow back through every step, through each spike by the surrogate gradient (section 2.5), and through each rounded weight by the straight-through estimator (section 4.4).
  4. Update. Optionally clip large gradients, then take an optimizer step.

The optimizer is Adam, AdamW or SGD. Weight decay, a penalty that pulls parameters toward zero to reduce overfitting, applies only to convolution and linear weights. Applying it to τ, θ and batch normalization pulled those toward zero as well and changed what the network deployed with (section 2.3).

Augmentation

Augmentation changes each training clip slightly every time it is used, so the network cannot memorize the exact clips. The search can switch on four changes: shift the image by a few pixels, blank out a square, drop a fraction of the input values, and mirror the image left to right. Each change is drawn once per clip and applied the same way at every step, so motion within the clip is kept. Mirroring is used only when the dataset says a mirrored example keeps its label; DVS128 Gesture has separate left-hand and right-hand gestures, so it is never mirrored. Every changed clip is still made of whole input values the chip could receive. Validation and the simulator check always see the clips unchanged.

A run can also be given a seed, a number that fixes its random starting weights, the order of its training batches and its augmentation. The same seed repeats a run exactly. The search uses this to retrain its best networks with several new seeds (section 6.6).

Cosine and onecycle deliver most of their benefit late in the run. Section 6.4 relies on that property when deciding how early a trial may be stopped.

After each epoch the network is scored on validation. With only 216 validation clips, one epoch's score can swing by a couple of points by chance, so picking the single best epoch tends to pick a lucky one. The tool keeps the weights from the end of the best five-epoch stretch instead, judged by its average.

5.6What one run produces

PhaseWhat happens
warm-upAbout a quarter of the epochs train normally, with batch normalization, so its running averages settle.
on the gridThe best warm-up weights are reloaded, batch normalization is folded in, and the remaining epochs train on rounded weights at half the learning rate.
exportThe network is frozen into its deployable form and scored on validation.
simulator checkThe validation clips run through IntegerSim, and every prediction is compared with the PyTorch model's (section 4.6).

Each run reports, among other things:

hw_val_accuracy
Validation accuracy of the deployable network, computed in PyTorch.
sim_val_accuracy
The same clips on IntegerSim.
sim_disagreements
Clips where those two predict different gestures. Should be 0.
deployed_tau
The τ each layer ends up with. When τ is learned this can differ from where it started.
synops_per_sample
Spike-triggered additions per clip (section 3.3).
hw_test_accuracy
Test accuracy, computed once when a single configuration is trained with main.py single. The search never sees it.

The saved checkpoint holds the trained network, the deployable network, the configuration, the metrics and each layer's integer thresholds and τ, so the network can be exported to the chip without retraining.
