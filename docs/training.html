Training

How input becomes spikes, how the network's output spikes become a prediction, what happens in one training step, and what one training run reports. Page B covers the data itself and page C the order of the stages.

5.1Turning input into spikes

An input coding decides what the network receives at each step. Event recordings already have a time axis and arrive as frames of events (page B). A still image does not, and the choice of rule changes both accuracy and how many spikes the network fires.

CodingWhat it doesFits
levelsRounds each pixel to a whole number from 0 to 2B − 1 and feeds it at every step, on B input lines (page E).Still images on the chip. The default for still images.
directFeeds the same pixel values at every step.Still images in software. The chip's input lines carry spikes only, so this coding cannot run on the chip as is.
poissonEach step, fires a pixel with probability equal to its brightness.Still images on the chip. The randomness costs accuracy at small T.
temporalEach pixel fires once; brighter pixels fire earlier.The fewest spikes, and the hardest to train.
passthroughShrinks event frames and turns any nonzero pixel into a spike, or with B bits, into its event count up to 2B − 1.Event cameras, including DVS128 Gesture.

Shrinking without losing events

A 128×128 frame with two channels needs 32,768 input axons, and the chip has 16,000, so frames are shrunk first. The search works out its range of sizes from the dataset: from about a quarter of the largest size up to the native size or the largest square that fits in 16,000 axons, whichever is smaller. For DVS128 Gesture that is 24×24 to 88×88 (2 × 88 × 88 = 15,488 axons). A 32×32 color image fits at full size.

Shrinking by averaging neighboring pixels has a problem with sparse events. A lone event becomes a small fraction, which no spike can represent. That motivates the passthrough coding's rule: any nonzero result becomes a full spike, so no event disappears.

Under the threshold rule an isolated event survives the reduction. Under averaging it becomes a small fractional value with no spiking equivalent.

With more than one bit per pixel, the passthrough coding keeps each pixel's event count instead of a single spike, and sends it in binary on several input lines. 5.2Reading a prediction

The last layer has one neuron per class (11 for the gestures), and each fires a train of spikes across the clip. The prediction is the class whose neuron fired most. During training, the spike rates act as class scores in a cross-entropy loss. Label smoothing moves a little of the target away from the correct class, which discourages overconfidence.

5.3Letting the last frames arrive

Each spiking layer delays its output by one step (section 2.1). When the input ends after T frames, the effect of the last frames is still on its way to the output. Stopping at T would discard it, and a deeper network would lose more.

So after the T input frames the tool runs one extra step per spiking layer with no input, called flush steps, and counts output spikes throughout. The count is divided by T so scores stay comparable across depths. A max pool adds one more flush step, since its OR neurons are a layer of chip neurons too. The simulator check runs the same number of steps.

Follow the last frame through two layers

Take two spiking layers and T input frames. Layer 1 adds frame T to its potential at step T and can fire about it at step T+1, when layer 2 receives that spike; layer 2 can then fire at T+2. Two flush steps let both responses reach the count.

5.4One training step, in detail

Page C draws the step as a flow. Here is what each part does.

  1. Forward. A batch of clips, shape (N, T, C, H, W), goes through the network for T plus flush steps, giving one spike rate per class for each clip. Neuron state is then reset so clips do not affect each other.
  2. Loss. Cross-entropy between the rates and the true classes. The search also tries TET (temporal efficient training, Deng et al., 2022), which averages a cross-entropy computed at every step, so each step learns to classify on its own. The prediction is the rate either way.
  3. Backward. Gradients flow back through every step, through each spike by the surrogate gradient (section 2.5), and through each rounded weight by the straight-through estimator (section 4.4).
  4. Update. Optionally clip large gradients, then take an optimizer step.

The optimizer is Adam or AdamW. Weight decay, a penalty that pulls parameters toward zero to reduce overfitting, applies only to convolution and linear weights. Applied to τ, θ and batch normalization, it would pull those toward zero as well and change what the network deploys with (section 2.3).

Augmentation and seeds

Augmentation changes each training clip slightly every time it is used, so the network cannot memorize the exact clips (page B shows each change). Every changed clip is still made of whole input values the chip could receive. Mirroring is used only when the dataset says a mirrored example keeps its label, which rules it out for DVS128 Gesture with its separate left-hand and right-hand gestures. Validation and the simulator check always see the clips unchanged.

A run can also be given a seed, a number that fixes its random starting weights, the order of its training batches and its augmentation. The same seed repeats a run exactly. The search uses this to retrain its best networks with several new seeds before it names a winner (page C).

Cosine and onecycle deliver most of their benefit late in the run. Section 6.4 relies on that property when deciding how early a trial may be stopped.

After each epoch the network is scored on validation. With only 216 validation clips, one epoch's score can swing by a couple of points by chance, so picking the single best epoch tends to pick a lucky one. The tool keeps the weights from the end of the best five-epoch stretch instead, judged by its average.

5.5What one run produces

PhaseWhat happens
warm-upAbout a quarter of the epochs train normally, with batch normalization, so its running averages settle.
on the gridThe best warm-up weights are reloaded, batch normalization is folded in, and the remaining epochs train on rounded weights at half the learning rate.
exportThe network is frozen into its deployable form and scored on validation.
simulator checkThe validation clips run through the fast chip simulator, and every prediction is compared with the PyTorch model's (section 4.6).

Each run reports, among other things:

deployed accuracy
Validation accuracy of the deployable network, computed in PyTorch.
simulator accuracy
Validation accuracy of the same network on the chip simulator.
disagreements
Clips where those two predict different gestures. Should be 0.
deployed τ
The τ each layer ends up with. When τ is learned this can differ from where it started.
SynOps per clip
Spike-triggered additions per clip (section 3.3).
test accuracy
Measured once, on a single final network. The search never sees it.

A saved run holds the trained network, the deployable network, its settings, its measurements and each layer's integer thresholds and τ, so the network can be exported to the chip without retraining.
