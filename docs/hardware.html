Fitting the chip

A trained network has to pass three tests before it can run on HiAER-Spike. It must fit the connection limits, its numbers must fit 16-bit integers, and its batch normalization must be removed. This page covers each test, and how the tool then checks the finished network on a simulator of the chip.

4.1Connection limits

The chip keeps its connections in tables of fixed size, so a network with too many connections into or out of one neuron cannot be stored. The layer sizes from section 3.2 are enough to check this before training, which saves the GPU time a doomed network would waste. check_feasibility() runs first in every trial and returns the list of limits a network breaks.

For a convolution layer with a k×k kernel, stride s, Cin input channels and Cout output channels:

  • Fan-in of one neuron is k² · Cin, the window it reads.
  • Fan-out of one input neuron is ⌈k/s⌉² · Cout, the number of windows that contain it.
  • Input axons are height × width × channels of the input image, times the bits per pixel (section 5.2).
  • A head neuron reads everything the last convolution layer produces.

Pooling multiplies fan-in

An average pool has no neurons on the chip. It is folded into the next layer: each of the four neurons in a 2×2 block connects directly to the next layer, carrying the next layer's weight, and that layer's potential is kept in units four times finer so the arithmetic stays exact. The next layer's fan-in is therefore four times k² · Cin. The same holds for a head after a pool, and for GAP, which averages over the whole image: every head neuron connects to every neuron of the last convolution layer.

The first search counted fan-in after pooling instead of before, and so it accepted networks the chip cannot hold. Its best network pools twice, and each of its 11 output neurons needs 32,256 connections, against a limit of 8,159. Two other ways to shrink the image avoid this cost. A stride-2 convolution has no pool to fold.

Max pooling as OR neurons

A max pool of spikes asks whether any input in the window fired. One chip neuron answers that exactly: give it weight 1 from each input and a threshold of 0, so it fires whenever its total is at least 1. Each window gets one such OR neuron, and the next layer reads the pooled values, so its fan-in stays at the pooled size. The OR neuron fires one step after its input, like every chip neuron, and training includes that step. With max pooling, the best network's design needs 8,064 connections per output neuron and fits.

Signed spikes

A chip neuron can only send a positive spike. The search also tries layers whose units send +1 or −1. Each such unit is two chip neurons: one adds up the unit's input and the other adds up its negative, each with its own threshold. The second neuron's outgoing connections carry negated weights, so the next layer receives +w or −w. Every neuron of a signed unit connects to both neurons of each unit in the next layer, so fan-in and fan-out double, and the chip check counts them that way. A max pool stays exact with one OR neuron per sign.

4.216-bit weights

The chip stores weights as 16-bit integers from −32,767 to 32,767, so a trained weight such as 0.7 has to become one of them. The scale w_alpha says what real value the largest integer stands for:

stored = round( w / w_alpha × 32767 ) read back = stored × w_alpha / 32767

This project uses w_alpha = 1, as the HiAER-Spike conversion does. The grid then covers [−1, 1] in steps of about 0.00003, so rounding a weight inside that range barely changes it. A weight outside the range is clipped: 1.3 becomes 1.0. Clipping is where accuracy is lost, and section 4.3 shows where large weights come from.

Thresholds use the same scale. A neuron compares its potential, which is a sum of weights, against θ, so both sides must be in the same units. That is why θ must lie in (0, 1].

4.3Removing batch normalization

Batch normalization rescales and shifts each channel during training, which makes deep networks train much more reliably. The chip has no such layer. Because a convolution followed by batch normalization is just two linear steps, the pair can be merged into one convolution with new weights W′ and a new bias b′, per output channel c:

W′c = Wc · γc / √(σ²c + ε) b′c = βc − μc · γc / √(σ²c + ε)

Here μ and σ² are the channel's average and variance seen during training, and γ and β are the scale and shift batch normalization learned. This is called folding. Folding causes two problems on the chip.

Weights grow

The factor γ/√(σ² + ε) is often greater than 1, so folding can push weights past 1.0, where section 4.2 clips them. A weight of 0.6 in a channel with a factor of 2.1 becomes 1.26 and is stored as 1.0. Clipping after training would change the network without warning, which motivates folding during training (section 4.5), so training sees the clipped weights and adapts to them.

A bias appears

Folding produces a bias b′ for every channel, even if the convolution had none, and the chip's neurons have no bias term. The tool offers two ways to deploy it, and the search tries both.

threshold
Fold b′ into the threshold: the neuron fires when v > θ − b′. This costs nothing on the chip. It is only an approximation of a bias, because a bias adds b′ on every step and builds up against the leak, while a threshold shift counts once. Training uses the same threshold form, so the trained network and the deployed one still match.
bias neurons
Deploy b′ as a real bias. A bias neuron is an always-on neuron (in hs_api, an ANN_neuron with threshold −1) that fires on every step. Its connection weight is the bias, so every neuron it connects to receives b′ on every step. This is exact. It costs one bias neuron per channel and one connection per neuron, and more when a bias is too large for one 16-bit connection or a channel has more than 4,095 neurons. The tool splits those across several bias neurons automatically.

A large positive b′ drives the folded threshold to zero or below, which makes the neuron fire on every timestep. deployment_report() treats that as a blocking condition and the search scores the configuration zero. fold_bias_report() prints the ratio |b′|/θ per convolution as an advance warning.

In threshold mode, θ − b′ must stay inside (0, 1]. If b′ grows larger than θ, the folded threshold drops to zero or below and the neuron fires on every step. That motivates keeping b′ inside the legal band throughout training, by clamping it in the forward pass, so the optimizer learns a bias the chip can store.

4.4Training on the integer grid

Rounding to the grid has a slope of zero almost everywhere, so ordinary backpropagation would stop at every rounded weight. The tool uses the straight-through estimator: the forward pass uses the rounded, clipped weight, and the backward pass treats the rounding as if it were not there, passing the gradient on unchanged.

So each weight exists twice. The stored value is an ordinary floating-point number that the optimizer updates. The used value is that number clipped and rounded, and it is what the network computes with. If the stored value is 1.3, the network uses 1.0, and small updates keep accumulating on the stored value until it moves back inside the range. At export, the used value is what gets saved.

def fake_quantize_weight(w):
    b = W_BITS - 1                                  # quantizer uses w_bit - 1
    levels = 2 ** b - 1
    wc = torch.clamp(w / W_ALPHA, min=-1.0, max=1.0)
    q = torch.round(wc.abs() * levels) / levels * torch.sign(wc) * W_ALPHA
    return _ste(q, w)

One consequence for measurement: the share of weights being clipped has to be read from the stored values. Reading the used values always reports zero, because they have already been clipped.

4.5When to fold

Folding needs batch normalization's running averages, which mean little until the network has seen some data. Folding too late leaves no time to adapt to clipping. The tool offers three schedules.

At the end of training, export_deployed() turns each folded layer into a plain convolution holding its final integer weights, and puts each bias where its mode says: into the thresholds, or onto the convolution for bias neurons. Two functions then inspect the result. deployment_report() checks that every threshold is legal and reports how many weights were clipped. hardware_export() writes each layer's integer thresholds, τ and leak shift.

4.6Checking the finished network on a simulator

A mistake in any step above lowers accuracy without raising an error, so the tool checks the finished network instead of trusting the steps.

The reference is simpleSim, the simulator of the chip that ships with hs_api. It is the target used for now because, according to the hs_api team's own tests, the current FPGA build handles the leak of negative potentials incorrectly. simpleSim stores every connection as a separate Python object. The best network found so far has 239 million connections, which would take about 150 GB of memory and several hours to load before simulating a single clip.

That cost motivated IntegerSim (snnsearch/hs_export.py). It performs simpleSim's exact arithmetic, step by step, but keeps each convolution as a convolution instead of listing its connections. Every value is an integer, held exactly. It runs all 464 validation and test clips of the best network in about 20 seconds on a laptop GPU.

Source: snnsearch/hs_export.py
snnsearch/hs_export.pyIntegerSim.steps
@torch.no_grad()
def steps(self, frames, flush_steps):
    T = frames.shape[0]
    zeros = torch.zeros_like(frames[0])
    V = None
    for t in range(T + flush_steps):
        x = (frames[t] if t < T else zeros).to(self.device, torch.float64).unsqueeze(0)
        if V is None:
            V, h = [], x
            for i in range(len(self.layers)):
                h = self._drive(i, h)
                V.append(torch.zeros(h.shape, dtype=torch.float64, device=self.device))
        # phase one
        spikes = []
        for i in range(len(self.layers)):
            s = (V[i] > self.th[i]).to(torch.float64)
            V[i] = V[i] * (1.0 - s)
            if self.memoryless[i]:
                V[i] = torch.zeros_like(V[i])
            else:
                V[i] = V[i] - torch.floor(V[i] / self.div[i])
            spikes.append(s)
        # phase two
        V[0] = V[0] + self._drive(0, x)
        for i in range(1, len(self.layers)):
            V[i] = V[i] + self._drive(i, spikes[i - 1])
        for i, b in enumerate(self.b):
            if b is not None:
                V[i] = V[i] + b
        # simpleSim's membrane is a 32-bit integer that wraps (35-bit and
        # saturating on older commits); float64 does neither, so the two
        # agree only while nothing gets near the rail
        peak = max(float(v.abs().max()) for v in V)
        self.max_abs_membrane = max(getattr(self, "max_abs_membrane", 0.0), peak)
        if peak >= MEMBRANE_LIMIT:
            raise OverflowError(
                f"membrane reached {peak:.0f}, past simpleSim's 32-bit range "
                f"({MEMBRANE_LIMIT}); IntegerSim no longer matches it")
        yield V, spikes

IntegerSim earns its place through a self-test (python tools/match_simplesim.py --selftest). The test builds 18 small networks covering every layer type the tool deploys: convolutions, average pooling, GAP, and bias neurons. It runs each one through both IntegerSim and the real simpleSim, and compares every neuron's potential and spike at every step. All 18 match exactly. The test also catches deliberate one-unit errors in the threshold, the bias and the leak.

Every trial in a search now runs its validation clips through IntegerSim and records two numbers: the simulator's accuracy, and how many clips the simulator and the PyTorch model classify differently. That second number should be zero. For the best network so far it is zero on all 464 clips.
