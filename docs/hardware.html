Fitting the chip

A network has to pass three tests before it can run on HiAER-Spike. It must fit the connection limits, its numbers must fit 16-bit integers, and its batch normalization must be removed. This page works out a network's size, then covers each test and what it costs.

G.1Working out layer sizes once

Before anything is trained, the tool works out the size of every layer from the network's settings. Three parts of the tool need those sizes: the step that builds the network, the check against the chip's limits, and the count of neurons and connections. Computing sizes separately in three places lets them drift apart, which motivates one planner whose output all three read.

Each layer's output size comes from the standard convolution formula:

out = ⌊( in + 2·padding − (kernel − 1) − 1 ) / stride⌋ + 1

For example, a 64×64 image through a 7×7 kernel at stride 2 with no padding gives ⌊(64 − 7)/2⌋ + 1 = 29, so 29×29.

While walking the stack, the planner applies three rules.

  1. Stop shrinking small images. Once an image is 3×3 or smaller, later layers keep its size instead of shrinking it further. A kernel larger than the image is rejected with the sizes involved.
  2. Decide where shrinking happens. A layer that asks for pooling gets a stride-1 convolution followed by a pool. Otherwise the settings choose between a stride-2 convolution and a pool.
  3. Record three sizes per layer. The input size, the size after the convolution (where the neurons sit), and the size after pooling (what the next layer reads).

The third rule matters for the chip. An average pool has no neurons of its own, so the chip check needs the size before the pool, where the neurons are, and the size after it, which sets how the next layer is wired (G.3).

G.2Four ways to measure size

"How big is this network" has four different answers, because a convolution reuses one small filter at every position of the image. For a layer with a k×k kernel, Cin input channels, Cout output channels and an H×W output:

MeasureFormulaWhat it counts
neuronsCout · H · WSpiking neurons on the chip, one per output position per channel.
connectionsneurons · k² · CinSynapses the chip stores. Every neuron gets its own copy of the filter.
parametersk² · Cin · CoutNumbers that training learns. The filter is shared, so this is far smaller than the connection count.
SynOps (synaptic operations)Σ spikes × fan-outAdditions actually performed on a real clip. Measured, since it depends on the input as well as the shape.

A synaptic operation, or SynOp, is one addition at a neuron caused by an arriving spike. Neuromorphic papers report SynOps per input as a stand-in for energy, so every run measures it. A conventional network of the same shape would do one multiply-add per connection per step regardless of activity, which gives a fair comparison point.

The search can use SynOps four ways when choosing between networks:

ModeWhat it optimizesWhen to use it
accuracyAccuracy only. SynOps are recorded.The default.
constrainedAccuracy, scoring zero above a SynOps budget.When there is a fixed power budget.
weightedaccuracy − weight × SynOps / referenceWhen you can say how much accuracy a halving of SynOps is worth.
paretoBoth, keeping every network that no other network beats on both.When the trade-off is not decided yet.
A worked example

A convolution with 32 input channels, 32 output channels and a 7×7 kernel has 32 × 32 × 7 × 7 = 50,176 parameters. With a 12×12 output it has 32 × 12 × 12 = 4,608 neurons. Each neuron reads its own 7×7×32 window, so the chip stores 4,608 × 1,568 = 7,225,344 connections.

Neither count says how many additions happen during a clip. A neuron that never fires causes none, and one that fires on every step causes one per connection per step. SynOps depend on both the wiring and the input.

G.3Connection limits

The chip keeps its connections in tables of fixed size, so a network with too many connections into or out of one neuron cannot be stored. The layer sizes from G.1 are enough to check this before training, which saves the GPU time a doomed network would waste. Every trial runs this chip check first, and it lists every limit a network breaks.

For a convolution layer with a k×k kernel, stride s, Cin input channels and Cout output channels:

  • Fan-in of one neuron is k² · Cin, the window it reads.
  • Fan-out of one input neuron is ⌈k/s⌉² · Cout, the number of windows that contain it.
  • Input axons are height × width × channels of the input image, times the bits per pixel (page E).
  • A head neuron reads everything the last convolution layer produces.

Pooling multiplies fan-in

An average pool has no neurons on the chip. It is folded into the next layer: each of the four neurons in a 2×2 block connects directly to the next layer, carrying the next layer's weight, and that layer's potential is kept in units four times finer so the arithmetic stays exact. The next layer's fan-in is therefore four times k² · Cin. The same holds for a head after a pool, and for GAP, which averages over the whole image: every head neuron connects to every neuron of the last convolution layer.

Counted after the pool, such a layer would look four times cheaper than it is, so the chip check counts fan-in in front of every pool. A network that pools twice before a flatten head shows how large the effect gets: each of its 11 output neurons needs 32,256 connections, against a limit of 8,159. Two other ways to shrink the image avoid this cost. A stride-2 convolution has no pool to fold, and a max pool runs on neurons of its own.

Max pooling as OR neurons

A max pool of spikes asks whether any input in the window fired. One chip neuron answers that exactly: give it weight 1 from each input and a threshold of 0, so it fires whenever its total is at least 1. Each window gets one such OR neuron, and the next layer reads the pooled values, so its fan-in stays at the pooled size. The OR neuron fires one step after its input, like every chip neuron, and training includes that step. With max pooling, the two-pool network above needs 8,064 connections per output neuron and fits.

Signed spikes

A signed unit (page A) is two chip neurons, and each connects to both neurons of every unit it feeds, so the check doubles fan-in and fan-out for signed layers.

G.416-bit weights

Why this exists

Every connection on the chip stores its own weight, and a large network has millions of connections. Sixteen bits per weight takes half the memory of the 32-bit decimals training normally uses, and whole numbers need only small adding circuits, so one chip holds more neurons and spends less energy per spike. The price is that every weight gets rounded.

The chip stores weights as 16-bit integers from −32,767 to 32,767, so a trained weight such as 0.7 has to become one of them. The weight scale α says what real value the largest integer stands for:

stored = round( w / α × 32767 ) read back = stored × α / 32767

This project uses α = 1, as the HiAER-Spike conversion does. The grid then covers [−1, 1] in steps of about 0.00003, so rounding a weight inside that range barely changes it. A weight outside the range is clipped: 1.3 becomes 1.0. Clipping is where accuracy is lost, and G.5 shows where large weights come from.

Thresholds use the same scale. A neuron compares its potential, which is a sum of weights, against θ, so both sides must be in the same units. That is why θ must lie in (0, 1].

G.5Removing batch normalization

Why this exists

A chip neuron only adds up the weights its incoming spikes deliver. Batch normalization would make every neuron multiply and shift its total on every step as well, which costs circuit area and energy. Folding builds that scaling into the weights and threshold once, before the network goes on the chip, so the neuron gets the same effect with nothing extra to compute.

Before this section
  • A.1 One artificial neuron: what a bias is.

Batch normalization rescales and shifts each channel during training, which makes deep networks train much more reliably. The chip has no such layer. Because a convolution followed by batch normalization is just two linear steps, the pair can be merged into one convolution with new weights W′ and a new bias b′, per output channel c:

W′c = Wc · γc / √(σ²c + ε) b′c = βc − μc · γc / √(σ²c + ε)

Here μ and σ² are the channel's average and variance seen during training, and γ and β are the scale and shift batch normalization learned. This is called folding. It happens at the switch to integer weights a quarter of the way through training (page C), once batch normalization has collected real averages, and it leaves no normalization step on the chip.

Folding causes two problems on the chip.

Weights grow

The factor γ/√(σ² + ε) is often greater than 1, so folding can push weights past 1.0, where G.4 clips them. A weight of 0.6 in a channel with a factor of 2.1 becomes 1.26 and is stored as 1.0. Clipping after training would change the network without warning, which motivates folding during training (at the switch, page C), so training sees the clipped weights and adapts to them.

A bias appears

Folding produces a bias b′ for every channel, even if the convolution had none, and the chip's neurons have no bias term. There are two ways to deploy it, and the search tries both.

threshold
Fold b′ into the threshold: the neuron fires when v > θ − b′. This costs nothing on the chip. It only approximates a bias, because a bias adds b′ on every step and builds up against the leak, while a threshold shift counts once. Training uses the same threshold form, so the trained network and the deployed one still match.
bias neurons
Deploy b′ as a real bias. A bias neuron has a negative threshold, so it fires on every step. Its connection weight is the bias, so every neuron it connects to receives b′ on every step. This is exact. It costs one bias neuron per channel and one connection per neuron, and more when a bias is too large for one 16-bit connection or a channel has more than 4,095 neurons. Those cases are split across several bias neurons automatically.

A large positive b′ drives the folded threshold to zero or below, which makes the neuron fire on every timestep. The deployment check treats that as blocking, and the search scores the network zero. Training also reports the ratio |b′|/θ for each layer as an early warning.

In threshold mode, θ − b′ must stay inside (0, 1]. If b′ grows larger than θ, the folded threshold drops to zero or below and the neuron fires on every step. That motivates keeping b′ inside the legal band throughout training, by clamping it in the forward pass, so the optimizer learns a bias the chip can store.

G.6Training on the integer grid

Before this section
  • A.3 and A.10: gradients, and passing them through a step.

Rounding to the grid has a slope of zero almost everywhere, so ordinary backpropagation would stop at every rounded weight. The tool uses the straight-through estimator: the forward pass uses the rounded, clipped weight, and the backward pass treats the rounding as if it were not there, passing the gradient on unchanged.

So each weight exists twice. The stored value is an ordinary floating-point number that the optimizer updates. The used value is that number clipped and rounded, and it is what the network computes with. If the stored value is 1.3, the network uses 1.0, and small updates keep accumulating on the stored value until it moves back inside the range. At export, the used value is what gets saved.

One consequence for measurement: the share of weights being clipped has to be read from the stored values. Reading the used values always reports zero, because they have already been clipped.

In the search recordsweight_clip_frac

The share of weights that ended up outside [−1, 1] and were clipped, read from the stored values. 0.0 for the example network: folding pushed no weight past the grid.
