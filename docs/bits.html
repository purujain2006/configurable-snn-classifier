Bit encoding

The chip's input lines carry one bit each: a spike, or nothing. This page shows how a pixel that saw several events gets its count onto the chip anyway, why the weights make it add up, what each extra bit costs, and how the work it causes is counted.

E.1One axon, one bit

Everything the chip receives arrives on input lines called axons, and at each timestep an axon either spikes or stays silent. With one bit per pixel, a pixel's axon spikes if any event landed on that pixel during the frame. Two events and twenty look the same.

That throws information away: a pixel the hand swept across many times is busier than one it barely touched. Multi-bit input keeps the count. With B bits per pixel, the count is capped at the largest number B bits can hold, 2B − 1, written in binary, and each bit gets its own axon.

Switch to 1 bit: every busy frame arrives as the same single spike, and the neuron can no longer tell a grazing touch from a full sweep. Now try 4 bits: the counts arrive in full, using up to four axon spikes per frame. Counts above the cap are clipped, as the frame with 9 events shows at 3 bits.

E.3Why the weights make it add up

Each axon's weight is the pixel's weight multiplied by its bit's place value: w for the 1s bit, 2w for the 2s bit, 4w for the 4s bit, and so on. Adding up whatever arrives gives exactly the count times w:

b0·w + b1·2w + b2·4w = (b0 + 2b1 + 4b2) · w = count · wFor a count of 5, written 101: the 1s and 4s axons fire and the neuron receives w + 4w = 5w. So the network can be trained as if it read the count directly, and the chip, delivering it bit by bit, computes exactly the same thing.

E.4What extra bits cost

Bits are not free. Every bit is another axon for every pixel, so the chip's 16,000 input axons cover a smaller frame. The first layer reads B times as many inputs per neuron. And because the top bit's weight is the pixel's weight times 2B−1, and that product must still fit in the chip's 16-bit weights, the first layer's weights get coarser with every extra bit.

E.5Counting the work

One synaptic operation (SynOp) is one spike arriving at one connection, so the work a pixel causes depends on how many of its bits are 1, not on the count itself. A count of 4, written 100, is a single spike on the 4s axon; a count of 3, written 011, is two spikes. Across a frame the first layer's work is the number of 1 bits times each axon's connections. Its ceiling is B times the work of a one-bit input, because each pixel has B axons.

E.6When more bits help

Extra bits help when pixels collect many events per frame and the difference between a busy pixel and a quiet one carries meaning: short clips cut into few frames, or frames shrunk a lot, so each pixel covers a large patch of the camera. They cost a smaller frame, a wider first layer and coarser first-layer weights.

In the balanced comparison of 96 networks (page D), one bit did as well as any: 54.7% for 1 bit, 50.8% for 2, 47.7% for 3 and 54.9% for 4, all within noise of each other, and every one of the twelve best networks the search has trained so far uses one bit. At the frame sizes and clip lengths that score best, a bigger frame is worth more than a count.

In short

An axon carries one bit. With B bits per pixel, the event count is capped at 2B − 1, written in binary, and sent on B axons whose weights double with each bit, so the neuron receives exactly count × w. Each bit costs axons, first-layer inputs and weight precision, and the work it causes is one SynOp per 1 bit per connection.
