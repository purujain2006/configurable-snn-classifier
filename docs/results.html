What the trials revealed

Six search runs are on record. What a trial's score means is not the same in all of them, because the objective changed partway through, and reading the record without that in mind produces confident nonsense. This page separates the trials by what was actually measured, works through how each statistic was chosen and what it licenses, and then reports what the data supports and what it still cannot answer.

7.1Two kinds of trial

Every trial reports a number called val_accuracy. In half the record that number is the accuracy of a network that was never converted, and in the other half it is the accuracy of the network the chip would actually run. Those are different quantities and they are not comparable.

Why the distinction decides everything else

A network trained in floating point and the same network after conversion differ in weight precision, threshold precision, leak resolution, neuron update order, and whether batch normalization is still present. Each difference moves the output.

So a high score before conversion is a claim about a network that cannot be built. It still tells you something, since a configuration that fails in floating point will not recover on hardware, so the number works as a ceiling. Only a converted score answers the question the project was set up to ask.

Trials scored before conversion

These runs stop at the end of training. Their score is floating-point validation accuracy, and no conversion was attempted, so nothing in them can tell you whether the network was deployable.

7.2How a trial gets its number

The two kinds of score are produced by the same function, on two different occasions, and the difference is easy to miss when reading the code.

During training, a report goes out every epoch. Both accuracy keys hold the same floating-point number here, so val_accuracy is standing in for something it does not yet have. 

    def report_fn(epoch, train_loss, train_acc, val_acc, best_val_acc, lr, phase="float"):

Why one key carries two meanings

Early stopping has to compare trials mid-flight, so it needs a value every epoch, and the only value available every epoch is the floating-point one. Selection has to pick a winner, so it needs the converted value, which exists once.

Rather than maintain two independent metrics, the code reports both keys every time and points each consumer at the one it needs. The scheduler watches float_val_accuracy and sees a curve. The sampler reads val_accuracy with scope="last", which ignores every report but the final one, so it sees the converted number and nothing else.

The cost of that arrangement is that a trial which never reaches its final report silently contributes a floating-point number to a selection process that believes it is reading a converted one. Section 7.8 shows two trials where exactly that happened.

7.3How to read these numbers

The statistics on this page are not the ones a first course would reach for, and the reasons are worth stating before any result is quoted.

Why no t-tests

A t-test assumes the values are roughly bell-shaped around a mean. Accuracy here is not. There is a cluster of networks sitting near chance, having failed to learn at all, and a spread of networks that did learn. Two lumps, not one.

The source study measured this directly and reported a Shapiro-Wilk W of 0.80 at p=1.8e−5, which is a firm rejection of normality. A mean over that distribution describes nothing real, so every test used here works on ranks instead: sort the values, compare positions. Rank tests do not care about the shape of the distribution.

two groups
Mann-Whitney U. Asks whether one group tends to rank above the other.
three or more groups
Kruskal-Wallis H. The same idea generalized.
two continuous quantities
Spearman ρ. Correlation computed on ranks rather than values.
a yes/no outcome
Chi-square, with Cramér's V as the effect size. Fisher's exact test when counts are small.
What a permutation p-value is, and why it is used here

The usual p-value comes from a formula that assumes a large sample. With 43 scored trials that assumption is doing real work and cannot be checked. A permutation test avoids the formula entirely.

Compute the statistic on the real data. Then shuffle the labels thousands of times, destroying any true relationship, and compute it again each time. The p-value is simply the fraction of shuffles that did as well as the real grouping. If one shuffle in a thousand matches it, the p-value is about 0.001, and no distributional assumption was needed to say so. 

def kruskal(groups, n_perm=PERM):
    groups = [np.asarray(g, float) for g in groups if len(g)]
    if len(groups) < 2:
        return float("nan"), float("nan")
    allv = np.concatenate(groups)
    sizes = [len(g) for g in groups]
    n = len(allv)
    def stat(v):
        r, out, i = rank(v), 0.0, 0
        for s in sizes:
            out += (r[i:i + s].sum() ** 2) / s
            i += s
        return 12.0 / (n * (n + 1)) * out - 3 * (n + 1)
    obs = stat(allv)
    perm = np.array([stat(RNG.permutation(allv)) for _ in range(n_perm // 4)])
    return obs, float((np.sum(perm >= obs) + 1) / (len(perm) + 1))
Why the effect size matters more than the p-value

A p-value answers one narrow question: could this pattern plausibly have come from noise. It says nothing about whether the effect is large enough to act on. With enough samples a meaningless difference becomes significant, and with few samples a large one may not.

So each result below carries a magnitude alongside its p-value. Cramér's V and rank-biserial r run from 0 to 1. Spearman's ρ runs from −1 to 1 and is its own effect size. As a rough reading, 0.1 is small, 0.3 is moderate, 0.5 and above is large.

What FDR correction does, and why some strong-looking results are marked insignificant

Testing fifteen settings at once means fifteen chances to find something by accident. At the usual 5% threshold you would expect roughly one false positive per twenty tests, so a table of fifteen raw p-values will contain apparent findings that are not there.

The Benjamini-Hochberg procedure adjusts for that, producing a corrected value written q. Depth is the example in the source study: a raw p of 0.033 becomes q=0.082, which falls short of the threshold. The recomputation on this page tests claims one at a time rather than sweeping fifteen, so it reports p, and should be read as the more permissive of the two.

The limit none of this can fix

Every trial here was proposed by a sampler that deliberately concentrates on promising regions. That is what makes the search efficient and what makes its output hard to interpret: the good configurations resemble each other, so low τ, batch normalization and 32 channels arrive together and their individual contributions cannot be separated.

Early stopping compounds it. A pruned trial's accuracy is a floor rather than a result, biased low, and pruning is not random, so any setting correlated with surviving pruning will appear correlated with accuracy.

The clean answer is a controlled comparison: freeze the best configuration, vary one setting, run each to completion. That has not been done, so everything below is a hypothesis worth testing rather than a measured effect.

7.4Recomputing the recorded statistics

Observation

Several ranges in the search space were narrowed on the strength of statistics written into comments. Those numbers decide which configurations the search is allowed to try, so a wrong one silently removes good designs from consideration for the rest of the project.

Consequence

A claim that constrains future work has to be reproducible from the data that produced it. Each one was recomputed from the raw trial files, using permutation tests rather than asymptotic approximations, since 43 scored trials is too few for the usual large-sample arguments.

In code

tools/trial_analysis.py reads every leaderboard and rejection log, implements chi-square, Cramér's V, Kruskal-Wallis, Spearman and Mann-Whitney directly, and prints a verdict per claim. Its full output is kept alongside the site.

The one that needed its source

The normalization claim does not reproduce on these four runs. Only five trials here ran without normalization and one of them reached 0.7159, so the permutation test returns p=0.196.

The claim comes from a different pair of searches, recorded in docs/data/DVS_Search_Statistical_Analysis.xlsx. The claim is sound. Its wording overstates it slightly. An unnormalized network reached 0.733 in that study and 0.7159 in this one, so normalization is not a precondition for learning. What the data supports is that half of the unnormalized configurations fail outright, which makes it a question of risk rather than possibility.

A nuance the comment misses

The file treats τ's correlation with accuracy as an artifact of sampling a continuous value that the chip rounds away. The first half is right and the second half is not.

tools/trial_analysis.py · claim 6
  sampled tau range: 1.520 to 3.980
  distinct sampled values : 41
  distinct DEPLOYED values: 3   ->  [2, 3, 4]

  continuous tau vs accuracy: rho=-0.491  p=0.0008
  deployed  tau vs accuracy: rho=-0.392  p=0.0100

Forty-one sampled values collapse onto three, so the resolution the search was exploring is indeed imaginary. The correlation survives the collapse: τ=2, 3 and 4 are genuinely different networks and lower values score better. Reopening the range was the right call, but the reason is that the search was measuring at the wrong resolution rather than measuring nothing.

The study's own caveats, which still apply

Thirty-five feasible trials is exploratory. The document says so directly, and describes itself as hypothesis-generating rather than confirmatory.

Early stopping censors the outcome. A pruned trial's best accuracy is a floor, biased low, so the τ and learning-rate correlations may be partly measuring which configurations survived pruning rather than which ones are better.

The sampler is not neutral. Optuna concentrates on promising regions, so low τ, batch normalization and 32 channels co-occur in the winners and their individual effects cannot be fully separated. The study recommends a controlled comparison, freezing the winner and varying one setting at a time, which has not been run.

7.6Where two results disagree

Observation

The study finds that lower weight decay scores better, with ρ=−0.473 at q=0.020. The folding work in section 4.3 raised the sampled floors on weight decay, because decay is what holds the folded distribution inside the representable range.

Consequence

The two findings pull the same knob in opposite directions. The accuracy measurement was taken before conversion, where a folded weight leaving the range costs nothing, so it cannot see the reason the floors were raised. Neither result is wrong and they cannot both be satisfied by one number.

In code

The current floors are 1e−5 for adamw and 1e−7 for adam, raised from 1e−8 because the old ranges were fitted against an objective that could not observe clipping. Every measured run since then reports weight_clip_frac of 0.0, so nothing yet shows the raise was needed.

This is the conflict section 4.3 describes as weight decay having two jobs, now with a number on each side. The clean resolution is to stop asking one value to do both, either by excluding normalization parameters from decay and controlling the folded range separately, or by moving the folded bias onto the convolution where the range problem does not arise.

Worth noting when reading the τ result alongside section 2.3: the study sampled τ continuously and found ρ=−0.599, and the winners sit between 1.5 and 1.9. Every value in that interval deploys as 2. The correlation is real and the resolution it was measured at is not available on chip.

7.8The deployment stage

Observation

Two trials in 82 produced a converted accuracy. Everything else was pruned by early stopping, rejected by the connection check, or ran under the older objective that never converted anything.

Consequence

Every statement about how the network behaves after conversion rests on two data points. That is enough to have found two concrete failures and one working export, and nowhere near enough to characterize the conversion in general.

In code

The deploy-phase report carries hw_val_accuracy, quant_gap, weight_clip_frac, min_threshold and deployable. A configuration deployment_report marks undeployable scores zero whatever its accuracy was.

Conversion did not cost accuracy

Both gaps are negative, meaning the converted network scored higher than the floating-point one. That is the intended behavior of the inline schedule rather than a surprise. The float figure is the best the warm-up phase reached before folding, and the remaining epochs train on the folded and quantized network, so the on-grid network keeps improving after the number it is being compared against stops moving.

Neither trial clipped a single weight. Combined with the largest folded weight sitting at 0.665 in the probe export, this is the evidence that the weight-range problem of section 4.3 is not currently binding.

What the record does not support

  • No configuration has completed a full training budget and then been converted. The converted accuracy ceiling is unknown rather than measured at 74.4%, and the 87.5% in section 7.5 was never put through conversion at all.
  • Both deployment failures come from short runs whose batch normalization statistics were still immature, which inflates the folded bias. The size of that effect on a converged run has not been measured.
  • The weight decay conflict in section 7.6 is unresolved. One number is currently serving two purposes that want opposite values.
  • tdBN and learnable neuron parameters have never been evaluated on a run healthy enough to judge them. Their only appearance is run A, where they are confounded with the configurations that failed.
  • No controlled comparison has been run. Every result here is observational, drawn from a sampler that deliberately concentrates on promising regions, so the winning settings co-occur and their individual contributions cannot be separated.
  • split_by is fixed at "number" in every run. The alternative has never been tried.
