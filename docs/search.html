The search

A search tries hundreds of network configurations on a fixed compute budget. Page C walks through its stages. This page covers the tools it uses, the checks it runs before it starts, how it decides which trials to stop and which settings to sample, and what it writes down.

6.1The parts

Each trial trains and scores one configuration. A hyperparameter is a choice made before training, such as a layer's width or the learning rate (how large each training update is). Searching means running many trials to find hyperparameters that score well.

Optuna
Proposes the next configuration to try. It looks at the scores of finished trials and proposes values near the good ones more often (page C shows how).
Ray Tune
Runs many trials at once across the available GPUs, two to a GPU here, collects their reports and saves the search's progress. See Ray's concepts guide.
ASHA
An early-stopping rule that comes with Ray Tune. It compares trials at set points in training and stops the weaker ones, so their GPU time goes to better ones.

This project's part is connecting those tools to its own planner, chip check, training procedure and simulator check, in that order, so each trial stops at the first stage that rules it out.

6.2Checking a search before it runs

A search runs for a day or more. A mistake in its setup, such as a missing package, a dataset path that exists only on another machine, a trial too large for its share of the GPU, or a bug in the steps after the trials finish, would otherwise surface hours in. That motivates a preflight, which runs every stage of a search in miniature on the machine the search will use.

  1. Check the settings against each other.
  2. Load the data.
  3. Build the largest network the search could propose and measure its memory on the GPU.
  4. Train two small networks and check them against the simulator.
  5. Run a six-trial search through Ray to the very end, including the steps after the trials.

The search refuses to start until a preflight has passed for the same settings and the same code, so a setup mistake costs minutes instead of a day.

6.3Different scores for different jobs

During training, the question is whether a trial deserves more time. At the end, the question is how well its deployable network does. These need separate scores.

epoch score
Validation accuracy reported every epoch while the trial trains, before export. ASHA reads this to decide which trials to stop.
deployed score
The score Optuna optimizes: the deployable network's validation accuracy, or zero if the network cannot be deployed.
simulator check
The chip simulator's accuracy on the same clips, and how many clips it classifies differently from the PyTorch model.

Keeping these apart means a good training curve is never mistaken for a good deployed network, and a trial that ASHA stopped is recorded as stopped instead of as a score of zero.

6.4Early stopping

ASHA lets every trial train for a grace period, then compares it with the others at checkpoints spaced by a reduction factor. With a grace period of 30 epochs and a factor of 3, the first checkpoint falls at epoch 30 of an 80-epoch budget, and roughly the best third of trials continue to the end. Trials start and finish at different times, so each is compared with whichever trials have reached the same checkpoint.

Two rules decide what the checkpoint is allowed to judge.

  • The first checkpoint comes after the switch to integer weights. The switch happens at epoch 20, and accuracy dips for a few epochs while the network adjusts. A checkpoint at or just after the switch would cut trials before they had trained on the weights they deploy with.
  • Trials in the balanced block are never stopped. Some options, such as augmentation and GAP heads, learn slowly at first and catch up later. The block exists to compare every option fairly (section 6.6), so every option there is judged on full runs.

Some learning-rate schedules improve most toward the end of training, so a grace period that is too short stops promising trials early. The demo shows the effect: set the grace period to 1 and the late-improving curves are cut.

6.5Sampling only what applies

Some settings exist only for some networks. A four-layer network has a kernel size for its fourth layer, and a two-layer network does not. Optuna's "define-by-run" mode builds each trial's settings step by step, so a trial only has the settings it actually used.

The order of those steps matters. The search samples the network's shape first, checks it against the chip, and only then samples training settings such as the learning rate. A rejected shape that was scored together with training settings it never used would teach Optuna that those training settings were bad. Stopping at the shape on failure means a rejected network only counts against its shape.

6.6What the search samples

Every setting, the values the search tries and how each one moved accuracy are on page D, one card per setting. The shape settings come first and are checked against the chip before anything else is sampled.

The balanced block

Optuna favors whatever has scored well so far, so an option that starts badly can end up barely tried, and too few trials remain to judge it. The search therefore begins with a block of 96 designed trials covering ten choices:

  • pooling: none, average or max
  • bias: in the threshold, or bias neurons
  • head: flatten or GAP
  • signed spikes: off or on
  • bits per pixel: one, or more than one
  • τ: fixed, learned per layer, or learned per channel
  • loss: rate or TET
  • augmentation, dropout between layers and the firing-rate penalty: each off or on

Every combination of all ten would take 2,304 trials. Instead, each option appears equally often across the block, and every pair of choices is spread as evenly as possible, so no option is mostly tried alongside one setting of another. Each trial in the block gets a random network shape that fits the chip, and Optuna samples the remaining settings. Optuna starts steering only after the block (page C draws it).

Retraining the finalists

The best score in a search is partly luck: each trial is one training run, and the highest of hundreds of noisy scores sits above the network's true level. So when the search ends, its five best configurations are trained again from scratch with three new seeds each, with no early stopping, and the winner is the configuration with the best average validation score (page C). The test set is still not used.

6.7What the search writes down

A search can run for days, and one that crashes near the end should not lose its results, so every result is written to disk the moment it arrives. Only one process writes, which keeps parallel trials from interleaving their records.
