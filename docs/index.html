Configurable SNN classifier

Spiking networks for HiAER-Spike

Brains recognize what they see while spending very little energy, because their neurons only do work when they send a spike. HiAER-Spike is a computer built at UC San Diego to work the same way. This tool searches for networks that can run on it and still recognize what they see, and checks every one on a simulator, a program that reproduces the chip's arithmetic exactly.

The test task is recognizing 11 hand gestures filmed with an event camera. The best network so far, chosen the fair way, by its score on people held out from training before the test set is looked at, classifies 85.4% of the test clips correctly when run on an exact software copy of the chip, and it fits the chip; the highest test score measured is 86.8%. That compares with 68.75% in the HiAER-Spike paper, on the same test set.

1What this is

HiAER-Spike is a neuromorphic computer, meaning one built to compute the way neurons in a brain communicate, with brief electrical pulses. It was developed at UC San Diego and runs on FPGAs, chips whose circuits can be reprogrammed after they are made. A GPU runs a neural network by multiplying large tables of numbers, every step. HiAER-Spike instead stores every neuron and every connection individually, and it does work only when a neuron sends a spike. A spike is a single event: one neuron signaling to the neurons it connects to that it has fired.

A spiking neuron keeps one number, its membrane potential. Input spikes raise it, it leaks back toward zero, and when it passes a threshold the neuron fires a spike and resets. This model is called leaky integrate-and-fire, and it is the one HiAER-Spike runs (page A animates it).

The tool takes a description of a family of networks, convolutional networks, which slide small learned filters across an image, and finds members of that family that can run on the chip and score well. It rejects networks the chip cannot hold before training them, trains the rest with the chip's own arithmetic, and checks every result clip by clip on a simulator, a program that computes exactly what the chip would.

2Why it matters

When most of a spiking network is silent, most of the work disappears. That is the promise of neuromorphic hardware: computers that see and hear on a tiny energy budget, close to the sensor. The promise only counts if real networks run on real chips with good accuracy, and that is hard for two reasons.

  • The chip has strict rules. A network trained the usual way breaks them: too many connections into one neuron, numbers too precise to store, operations the chip does not have. Converting such a network afterwards loses accuracy, and often it does not fit at all.
  • The choices are enormous. A network here has about thirty settings, from the size of the input to how each neuron leaks. Trillions of combinations exist, each one needs a full training run on a GPU to score, and no rule of thumb says which will fit and score well.

The search answers both. Every network it proposes fits the chip from the start, trains with the chip's arithmetic, and is scored on the chip simulator, so the best one it finds can be deployed exactly as it was measured. Along the way it measures how much each setting matters, which any spiking-network project on this chip can use.

3The chip's rules

Five terms come up throughout the site.

synapse
One connection from one neuron to another, holding one weight.
axon
An input line that carries spikes into the chip from outside. Here the outside is an event camera.
fan-in
The number of connections arriving at one neuron.
fan-out
The number of connections leaving one neuron.
INT16
A signed 16-bit integer, from −32,767 to 32,767. Every weight and threshold on the chip is one.

input axons16,000Each input pixel needs one axon per channel (one for brighter events, one for darker). A 128×128 camera needs 32,768, so frames must be shrunk first.
fan-in8,159The most connections one neuron can receive. This is the limit networks break most often.
fan-out4,095The most connections one neuron can send (4,096 for an axon).
weightsINT16, |w| ≤ 1The integer 32,767 stands for 1.0, so weights lie in [−1, 1] in steps of 1/32,767, about 0.00003. A larger weight is clipped to 1.
threshold0 < θ ≤ 1θ (theta) is the level a neuron's potential must pass before it fires. It is stored the same way as a weight, so it must lie between 0 and 1.
leakτ = 2, 4, 8, 16, …τ (tau) sets how fast a neuron's potential leaks away: each step it loses 1/τ of itself. The chip computes that by halving, the cheapest division a circuit can do, so τ must be a power of two.
biasnone built inNeurons have no bias term. A bias can be added with a bias neuron: a neuron that fires on every step and connects to every neuron that needs the bias, at the cost of one connection each.
normalizationnoneNo batch normalization, the layer that rescales each channel during training so deep networks train reliably. Its effect is merged into the weights before deployment, a step called folding (page G).
poolingfolded, or OR neuronsNo pooling step, the usual way to shrink a picture by averaging each 2×2 block or keeping its largest value. Averaging is merged into the next layer, which then needs four times as many connections. Keeping the largest is done by one extra neuron per block, at the cost of one step.
update orderfire firstFire, reset, leak, then integrate (page A). Each layer delays its output by one step.

4How the tool works

  1. Describe. A network is a list of settings: the layers, the neurons and the training recipe. A search gives each setting a range and samples networks from them.
  2. Check. Before any training, the tool works out every layer's size and compares fan-in, fan-out and axon count against the chip's limits. This is arithmetic, so a network that cannot fit is rejected in microseconds.
  3. Train with the chip's arithmetic. Training uses a neuron that follows the chip's update order, integer weights, a power-of-two leak, and batch normalization folded in. The network that trains is the network that deploys.
  4. Check on the simulator. Every trained network runs clip by clip through a simulator that does the chip's exact integer arithmetic. A validation set, held back from training, is used to score it and to choose between networks.
  5. Search. Each candidate network the search builds and trains is called a trial. A balanced first block of trials compares every option fairly. After it, the search concentrates on the options that scored well, stops weak trials early, and retrains the best few before naming a winner.

Page C follows one candidate through every stage, and then the search as a whole.

The search on the gesture task has trained 135 networks so far, each for up to 80 epochs, passes over the training data (page C). All 130 that trained to the end fit the chip and agree with the simulator on every validation clip; the other five were stopped early on purpose, because they were clearly losing. Its best five were then trained for 300 epochs, and the four that have finished score 80.6% to 86.8% on test. Three things now hold the scores back, and none of them is the chip: overfitting, learning the training people rather than the gestures; clips that may still be too short; and how few runs each number rests on. The networks also do more work than a conventional network so far, the next thing to fix. Page H explains each number and how far to trust it.
