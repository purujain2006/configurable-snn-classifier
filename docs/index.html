This site explains — from absolute zero — what a real 3,200-line research file (Practice2.py) does: it builds a spiking neural network that watches a special camera and recognizes hand gestures, then squeezes that network onto a brain-inspired chip called HiAER‑Spike. No prior knowledge of spiking networks (or much of anything) required. Every concept gets a demo you can poke.

1.1What you're actually looking at

Somewhere in this repository sits one Python file. It has no framework around it, no folder full of modules — just one long, extremely deliberate file. Here is its job description, in one breath:

Build a brain-inspired neural network whose every knob is configurable, check that a proposed network can physically fit on a neuromorphic chip before wasting GPU time on it, train it in a way that already respects the chip's brutal integer arithmetic, and let an automated search try hundreds of configurations to find one that scores >97.5% accuracy — measured on the version that actually runs on the chip, not the flattering floating-point version.

That last clause is the soul of the whole file. A recurring disaster in this field: you train a network on your GPU, it hits 95%, you convert it for the chip… and it scores 60%. The chip isn't broken — the network you trained and the network you deployed were quietly different networks. Nearly every unusual design decision in this code exists to make the trained thing and the deployed thing be the same thing.

1.2The task: 11 gestures, one weird camera

The dataset is DVS128 Gesture (IBM, 2017): people performing 11 hand gestures — clapping, waving each hand, rotating each arm clockwise and counter-clockwise, air-drums, air-guitar, an arm roll, and an "other" category. The network's job: watch a short clip, output which gesture it was.

But it wasn't filmed with a normal camera. A DVS — Dynamic Vision Sensor, also called an event camera — has no frames at all. Each of its 128×128 pixels works independently and fires a tiny message called an event only when the brightness at that pixel changes: one channel for "got brighter" (ON), one for "got darker" (OFF) — which is why the data has 2 channels instead of RGB's 3. A stationary background produces silence. A moving hand produces a crackling stream of events tracing its outline.

So the input is not a picture; it's a sparse stream of change. That is exactly the kind of signal spiking networks were born for — and it's why this pairing of camera and network is a classic. The code chops the event stream into T time-slices (usually 16) and feeds them to the network one slice at a time. More on that in chapter 5.

1.3Normal networks pass numbers. Spiking networks pass blips.

The neural networks you've probably heard of (the ones behind image classifiers and chatbots — call them ANNs, artificial neural networks) are giant calculators. Every "neuron" computes weighted sum → squashing function → pass the resulting number onward. The numbers are precise decimals like 0.7314, and every neuron computes every time, whether or not anything interesting is happening.

A spiking neural network (SNN) copies biology more literally. A spiking neuron doesn't output a decimal — it outputs either nothing or a spike: an all-or-nothing blip, a 1 in a sea of 0s. Internally it keeps a running tally called the membrane potential — think of it as a leaky bucket:

  • Every incoming spike pours a little water in (how much = the connection's weight; inhibitory weights scoop water out).
  • The bucket leaks constantly — old evidence fades. The leak speed is set by a constant called tau (τ).
  • If the water level crosses a threshold (θ), the neuron fires a spike of its own to everyone downstream, and the bucket empties (a reset).

This particular flavor is called LIF — Leaky Integrate-and-Fire — and it is the only neuron type this codebase deploys. Two enormous consequences follow from "output is 0 or 1":

  • Time is part of the computation. A single spike says almost nothing; how often and when a neuron fires carries the information. The network must be run for T timesteps and its output spikes counted.
  • Silence is free. When nothing spikes, downstream neurons do no work — no multiply, no add, nothing. Sparse input ⇒ tiny energy. This is why neuromorphic chips can run on milliwatts.

1.4The catch: the chip is a harsh landlord

Spikes-are-cheap only pays off on hardware built for spikes. The target here is HiAER‑Spike, a neuromorphic research platform (from UC San Diego — Hierarchical Address-Event Routing), programmed through its Python interface hs_api. Unlike a GPU — which will run whatever math you write — this chip has non-negotiable house rules, and the code treats them as physics:

LIMITS Wiring budgets

A neuron may listen to at most 8,159 other neurons (fan-in) and shout to at most 4,095 (fan-out). The input side gets 16,383 total input lines ("axons"). Design a layer that exceeds these and it cannot be wired up, period. Chapter 4 lets you trip these limits yourself.

INTEGERS No decimals on chip

Weights live on a 16-bit integer grid and are hard-clamped to [−1, +1] — a weight of 1.3 silently becomes 1.0. Thresholds become integers. Even the leak τ is an integer register: τ=2.1 and τ=2.4 deploy as the same network. Training must anticipate all of this.

And one more subtlety that costs real accuracy if ignored: the chip's neuron performs its internal steps in a different order than the standard software neuron — it fires based on the previous timestep's bucket level. Result: every layer delays the signal by one tick, like a bucket brigade. A 5-layer network needs 5 extra "flush" timesteps of empty input after the clip ends, or the final frames' evidence never reaches the output. The code models this during training so there are no surprises later (chapter 2 animates it).

1.7How the file is organized (and where this site covers it)

Practice2.py is written in numbered sections, like chapters of a book. A design rule worth noticing: sections 1–4 import no PyTorch — pure Python math — so the architecture planning and feasibility checking can run on any laptop with no GPU stack installed. The heavy machinery only loads when you actually train.
