Configurable SNN classifier

Spiking networks for HiAER-Spike

A lab tool for testing which spiking classifiers fit HiAER-Spike, a research computing platform that processes spikes. Researchers describe candidate networks in a configuration file, then compare their accuracy after the hardware-specific transformations.

The demonstration task is gesture recognition from an event camera. The tool searches network designs and records why candidates fail or continue. The strongest reported candidate correctly classifies 240 of 288 test recordings.

Passing this check only establishes that the input fits. Each layer must also pass its connection checks, and the trained parameters must survive conversion.

What the tool does with the remaining candidates
  1. Reject designs that exceed the configured connection limits. In the reported search, this removed 82 of 400 candidates before training.
  2. Train feasible designs and compare validation scores, measured on examples held aside for choosing settings. Early stopping ended 207 trials before the full training budget.
  3. Transform and evaluate the 111 completed models, then save their configurations and measurements for comparison. Five candidates were selected for longer training.

These counts show the decisions the tool made. They do not measure time saved against a manual workflow or prove that every stopped candidate would have finished poorly.

The current builder supports convolutional spiking classifiers. Supported models and extension work explains what can change through configuration and what needs new code.

How the neuron accumulates input

A spiking neural network, or SNN, replaces the continuous activation with a binary event. Each neuron keeps one number, the membrane potential v, and updates it over a sequence of timesteps.

  • Incoming spikes add their connection weights to v. Negative weights subtract.
  • Between updates v decays toward rest at a rate set by a constant τ. The amount removed each step is v/τ, so a larger τ leaks less and carries evidence for longer. Older input counts for less than recent input.
  • When v crosses a threshold θ, the neuron emits a spike and v returns to zero.

This neuron model is called leaky integrate-and-fire, abbreviated LIF, and it is the model HiAER-Spike implements. Its parameters are the leak τ, the threshold θ, and the reset value.

The order of those operations is fixed by the hardware, as listed in section 1.3, and it affects when spikes appear. At each timestep the neuron first compares the potential it carried in from the previous timestep against θ, then resets if it fired, then leaks, and only then adds the current input. Input arriving at timestep t therefore cannot produce an output spike before timestep t+1.

The output layer has one neuron per gesture class. Its prediction is the class with the most output spikes over the clip. The example below isolates one neuron so you can inspect how input, leak, and threshold determine its spikes.

Hardware and input data

1.1Introduction to HiAER-Spike

HiAER-Spike is a research platform developed at UC San Diego and controlled through the Python package hs_api. Each neuron stores a membrane potential, receives weighted spikes, and emits a spike when its potential exceeds a threshold. Connections and neuron parameters must fit the device’s storage limits.

Event-driven computation can reduce work when spike activity is sparse. Actual energy use also depends on memory traffic, routing, and static power.

1.2Conversion from a trained model to a hardware representation

PyTorch represents a convolution as a layer with shared weights. HiAER-Spike stores individual neurons and their connections. The converter in hs_api expands the layer into that representation and maps its parameters to the supported integer format.

Implementation details

The platform represents individual neurons, signed 16-bit integer values, and connections between neurons. The converter expands convolutional and fully connected layers into this representation.

A convolution needs one hardware neuron per output position and channel. The converter lists the connections feeding each neuron and maps the weights to signed 16-bit values.

The converter expands the network and maps its values to the hardware format. snnsearch/quantgrid.py mirrors the numeric mapping so training can account for quantization. This reduces one source of conversion mismatch, but does not guarantee unchanged accuracy.

Expansion by the Converter

For each output neuron, the converter records its input connections and their weights. A convolution with 32 input and 32 output channels, a 7×7 kernel, and a 12×12 output has 50,176 learned weights, 4,608 output neurons, and 7,225,344 expanded connections. Reusing a filter across 144 positions explains the difference between the weight and connection counts.

Four terms follow from that picture, and they appear throughout this project.

synapse
One connection between two neurons, holding one weight.
axon
An input line carrying spikes into the chip from outside. For our example, a DVS camera feeds these.
fan-in
How many connections arrive at one neuron.
fan-out
How many connections leave one neuron toward the next layer.

Axon count, fan-in, and fan-out have fixed hardware limits. A configuration that exceeds them cannot be represented by the platform’s routing tables.

Mapping floating-point onto int16

The converter uses a symmetric range from −32767 to +32767. With w_alpha = 1, the integer 32767 represents the real value 1.0. A floating-point weight such as 0.7 is rounded to the nearest value on this grid.

This brings up the issue of weights beyond 1.0, such as 1.3 which has no integer available to it. The converter replaces it with 1.0. Truncation loses information and must be accounted for. Within the range [-1,1], the spacing between neighboring integers is about 0.00003, so snapping to the nearest available integer has negligible loss of information.

Firing thresholds use the weight scale. The leak constant is rounded separately to an integer register value, as described in section 2.3.

Running it

After conversion, the network receives T input frames and then runs additional timesteps with zero input. These flush steps allow delayed spikes to reach the classifier. Section 5.4 explains how the implementation chooses the number of steps.

1.3Platform Limits

The routing table of fixed size and an int16 number format produce the following hardware limits.

ConstraintValueRestriction
input axons16,000 Total input lines into the chip. An input image larger than this cannot be presented at all.
neuron fan-in8,159 How many sources one neuron may listen to. Caps how large a window one convolution neuron may read, and the width of a fully connected layer.
neuron fan-out4,095 How many destinations one neuron may drive.
weight formatINT16, |w| ≤ 1 Weights are 16-bit integers on a fixed grid of 1/32767. Values outside the range are truncated rather than rescaled.
threshold formatint(θ · 32767) Firing thresholds, as mentioned earlier, have the same int16 limits. θ must stay within (0, 1].
leakINT16 The decay constant of a neuron snaps to the nearest integer, which is extremely detrimental to accuracy. While developing this program, statistical analysis showed that tau had the greatest effect on the accuracy during floating-point training.
available layersconv, linear, pool (restricted) No bias terms are allowed, as the platform only supports multiply-adds with weights and the routing table stores no bias. There is also no batch normalization, which is a layer that rescales each channel using statistics gathered during training.
neuron update orderN/A The neuron fires on the state it carried in from the previous timestep, resets, leaks, and integrates. Each layer therefore delays its output by one timestep.

Conversion changes both the numeric values and the timing of neuron updates. The training implementation models these changes so the converted network can be evaluated under the same conventions.

1.4Conventional neural networks

Most neural networks in use today are artificial neural networks, or ANNs. A unit in an ANN computes a weighted sum of its inputs, applies a nonlinear function, and passes the resulting number forward. Values are continuous, typically 32-bit floating point, and every unit evaluates on every input.

A convolutional neural network applies shared filters across an image. GPUs evaluate these filters using dense arithmetic. For HiAER-Spike, the connections must be expanded explicitly and the network must use the supported spiking neuron update.

1.7The workload: DVS128 Gesture

The dataset is DVS128 Gesture, published by IBM in 2017. It contains recordings of 29 people performing 11 gestures, including hand waves, arm rotations, air drums and air guitar, under three lighting conditions.

The recordings come from a dynamic vision sensor with a 128×128 pixel array. Pixels report changes in brightness asynchronously. Increases and decreases form the two polarity channels.

An event camera records brightness changes, so moving edges generate events while a stable background produces few. This provides a sparse input stream for a spiking network.

The code converts each recording into T frames by dividing the event stream into T groups of equal event count, then turning each group into an image by counting the events that landed on each pixel.

Search objective and code organization

1.8What the project sets out to do

A network for this chip has many free parameters: how many convolution layers, how wide, what kernel size, how the resolution is reduced, how many timesteps, what leak and threshold the neurons use, and how the network is trained. Some combinations exceed the connection limits in section 1.3 and cannot be built. Others fit but lose accuracy when their weights are quantized.

The search ranks configurations by validation accuracy after conversion. The original target was 97.5%. The current reported test scores are 78.8% to 83.3%, measured on a different split from the validation set. See Results for the candidates and evaluation procedure.

Implementation details

A network trained in floating point differs from the network the chip runs in weight precision, threshold precision, leak resolution, neuron update order, and the presence of batch normalization. Each difference changes the output, and none of them appear in a training accuracy figure.

Floating-point accuracy can differ from accuracy after conversion. Ranking by the converted result directly measures the form the project intends to deploy.

Each trial ends by converting its network into the deployable form and evaluating that instead. The resulting hw_val_accuracy is the value the search optimizes. A configuration that cannot be represented on the chip scores zero, whatever it reached during training.

1.9How the code is organized

The implementation is a Python package, snnsearch, with a separate launcher. Configuration, planning, and connection checks do not import a deep learning library, so those checks can run without PyTorch or a GPU.

The diagram below maps the modules onto the four jobs the package performs. Each leaf links to the page that covers it.

Running it

A run is described by a configuration file and started by one command. Flags override the file, so a saved config stays the record of intent while a flag varies one thing.

Source excerpt
terminalfive modes
python main.py check                              # what this machine is missing
python main.py summary -c configs/dvs128.yaml     # no torch, no dataset needed
python main.py single  -c configs/dvs128.yaml     # train one configuration
python main.py search  -c configs/cifar10.yaml    # the automated search
python main.py report  results/dvs128             # rebuild report.html
  • check reports which packages, which GPU and which dataset files are present, and what each missing one blocks.
  • summary prints the architecture table, the counts and the feasibility verdict. It imports no deep learning library, so it is the cheapest way to confirm an install works.
  • single trains one configuration, folds it, quantizes it and reports both accuracies with the gap between them.
  • search runs the automated search and writes results as it goes.
  • report rebuilds the HTML report from a finished run directory.

What a configuration file holds

The configuration file holds settings and names the Python callable that loads the dataset.

YAML supports comments alongside settings. The configuration uses them to record why particular search ranges were chosen.
