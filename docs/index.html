Configurable SNN classifier

Spiking networks for HiAER-Spike

This tool searches for spiking neural networks that can run on HiAER-Spike, a neuromorphic computer built at UC San Diego. You describe a family of networks in a configuration file. The tool rejects the ones the chip cannot hold, trains the rest with the chip's own arithmetic, and checks every result on a simulator of the chip.

The example task is recognizing 11 hand gestures filmed with an event camera. So far, the best network classifies 240 of 288 test clips (83.3%) on the chip simulator, against 68.75% in the HiAER-Spike paper. That network breaks one of the chip's connection limits, so the next search looks for one that fits.

1.1What HiAER-Spike is

HiAER-Spike is a neuromorphic computer, meaning one built to compute the way neurons in a brain communicate, with brief electrical pulses. It was developed at UC San Diego. It runs on FPGAs, chips whose circuits can be reprogrammed after they are made, and is programmed from Python through a package called hs_api. A GPU runs a neural network by multiplying large matrices. HiAER-Spike instead stores every neuron and every connection between neurons individually, and it does work only when a neuron sends a spike. A spike is a single event: one neuron signalling to the neurons it connects to that it has fired.

The chip runs one specific kind of neuron, keeps its connections in tables of fixed size, and stores every number as a 16-bit integer. Each of these rules limits which networks can run on it, and together they are why a network trained the usual way cannot simply be copied onto the chip. Section 1.4 lists the rules.

1.2What a spiking neuron does

A spiking neuron keeps one number, its membrane potential. Time moves in discrete steps. At each step, incoming spikes add their connection weights to the potential, the potential leaks a little toward zero, and if the potential is above a threshold the neuron fires a spike and resets to zero.

Two constants set the neuron's behavior. The leak constant τ (tau) controls how fast the potential fades: each step the neuron loses 1/τ of its potential, so a larger τ remembers input for longer. The threshold θ (theta) is the potential needed to fire. This model is called leaky integrate-and-fire, or LIF, and it is the one HiAER-Spike implements.

Start with weight 0.45 and threshold 1. With τ = 4 it takes several inputs close together to make the neuron fire, and a larger weight or a lower threshold needs fewer of them. Clear history before comparing settings so earlier input does not affect the comparison.

The order the chip uses

HiAER-Spike fires before it integrates. At each step the neuron first compares the potential it carried in from the previous step against θ, resets if it fired, leaks, and only then adds the new input. Input that arrives at step t can therefore cause a spike no earlier than step t+1, and a stack of five layers answers five steps after its input. Most spiking-network libraries add the input first, and page 2 explains why training has to use the chip's order instead.

1.3Why spikes can save work

A conventional network, called an artificial neural network or ANN, multiplies every input by its weight at every step, whether or not the input changed. A spiking network does work only where a spike arrives: one addition per spike per connection. When most inputs are silent, most of the work disappears.

Counting operations stands in for energy. Real energy use also depends on memory traffic and on the power the hardware draws while idle, which this project does not measure.

1.4The chip's rules

Five terms come up throughout the rest of the site.

synapse
One connection from one neuron to another, holding one weight.
axon
An input line that carries spikes into the chip from outside. Here the outside is an event camera.
fan-in
The number of connections arriving at one neuron.
fan-out
The number of connections leaving one neuron.
INT16
A signed 16-bit integer, from −32,767 to 32,767. Every weight and threshold on the chip is one.
RuleValueWhat it means for a network
input axons16,000Each input pixel needs one axon per channel. A 128×128 camera with two channels needs 32,768, so frames must be shrunk. The register can count to 16,383, but 16,000 is the most the current FPGA design has run.
fan-in8,159The most connections one neuron can receive. This is the limit networks break most often.
fan-out4,095The most connections one neuron can send (4,096 for an axon).
weightsINT16, |w| ≤ 1The integer 32,767 stands for 1.0, so weights lie in [−1, 1] in steps of 1/32,767, about 0.00003. A larger weight is clipped to 1.
threshold0 < θ ≤ 1Stored on the same grid as the weights.
leakτ = 2, 4, 8, 16, …The chip leaks by a bit shift, subtracting V >> k each step, so τ = 2k. Any τ that is not a power of two does not exist on the chip.
biasnone built inNeurons have no bias term. A bias can be added with a bias neuron: a neuron that fires on every step and connects to every neuron that needs the bias, at the cost of one connection each.
normalizationnoneNo batch normalization, the layer that rescales each channel during training so deep networks train reliably. Its effect is merged into the weights before deployment, a step called folding (page 4).
poolingfolded, or OR neuronsNo pooling operation. An average pool is folded into the next layer's connections, so every neuron in front of it connects straight to that layer, and a 2×2 pool multiplies that layer's fan-in by 4. A max pool of spikes asks whether any input fired, which one neuron with threshold 0 answers exactly, at the cost of one extra step.
update orderfire firstFire, reset, leak, then integrate (section 1.2). Each layer delays its output by one step.

The input limit is the first one a network meets. Pick a frame size to see whether it fits.

1.5The example task: DVS128 Gesture

DVS128 Gesture is a dataset IBM published in 2017. It contains 29 people performing 11 gestures, including hand waves, arm rotations, air drums and air guitar, under three lighting conditions.

Like most machine-learning data it is split three ways. Training data teaches the network. A validation set, held back from training, is used to choose between networks. The test set is used once, at the end, and is the only score comparable to published results. Here the test set is six people, none of whom appear in training.

The recordings come from a dynamic vision sensor, a camera whose 128×128 pixels each report when their own brightness changes, instead of sending whole frames. Moving edges produce events and a still background produces almost none, which suits a spiking network. Brightness increases and decreases form two input channels.

The tool groups each recording's events into T frames (16 by default), each holding the same number of events, and shrinks the frames to fit the axon limit.

1.6What the tool does

  1. Describe. A configuration file lists the layers, the neuron settings and the training settings. For a search it lists ranges, and the tool samples a network from them.
  2. Check. Before any training, the tool works out every layer's size and compares fan-in, fan-out and axon count against the chip's limits. This is arithmetic, so a network that cannot fit is rejected in microseconds.
  3. Train with the chip's arithmetic. Training uses a neuron that follows the chip's update order, integer weights, a power-of-two leak, and batch normalization folded in. The network that trains is the network that deploys.
  4. Check on the simulator. Every trained network runs through IntegerSim, a fast copy of the chip simulator's arithmetic, clip by clip. IntegerSim is itself checked against the simulator in hs_api.
  5. Search. Optuna proposes configurations, Ray runs many of them at once, and weak ones stop early. The search keeps the network with the best validation accuracy.

The tool builds convolutional classifiers, networks that slide small learned filters across an image, which is the standard design for image tasks. It builds them from a configuration. Page 3 lists what it can take in today and what extending it would involve.

1.8How the code is organized

The code is a Python package, snnsearch, started from main.py. The parts that plan a network and check it against the chip import no deep-learning library, so they run on any machine.
