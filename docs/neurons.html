The neuron

HiAER-Spike runs one kind of neuron, with a fixed update order, a leak that must be a power of two, and a threshold limited to (0, 1]. This page rebuilds that neuron in PyTorch and explains how a network made of it can be trained.

2.1The update rule

A leaky integrate-and-fire neuron stores one number, its membrane potential v. Three constants set its behavior.

τ
The leak. Each step v loses v/τ, rounded down. At τ = 2 half the potential remains after one step; at τ = 16, about 94% remains.
θ
The threshold. The neuron fires when v is greater than θ.
v_reset
The value v takes after firing, which is 0 here. Anything above θ is thrown away.

The input at each step is one number: the sum of the weights of the incoming connections whose source neuron fired. Weights can be negative, which lowers the potential. The chip performs four operations in a fixed order:

  1. Fire. Compare the potential carried in from the previous step against θ. Emit a spike if it is strictly greater.
  2. Reset. If the neuron fired, set the potential to 0.
  3. Leak. Subtract v/τ, rounded down.
  4. Integrate. Add this step's input at full size.

Because the neuron fires before it integrates, input arriving at step t can cause a spike no earlier than step t+1. A network with five spiking layers answers five steps after the input that caused the answer. Section 5.4 uses this.

Work through three steps by hand

Start at v = 0 with τ = 4, θ = 1, and an input of 0.6 on every step.

  1. Step 1: 0 is below θ, so no spike. The leak leaves 0, and the input raises v to 0.6.
  2. Step 2: 0.6 is below θ. The leak removes 0.6 / 4 = 0.15, and the input raises v to 1.05.
  3. Step 3: 1.05 is above θ, so the neuron fires and resets to 0. The input raises v to 0.6 again.

The spike comes one step after the potential first passed 1. Each layer of a network adds one such step.

2.2Matching the chip's update order

This project trains with SpikingJelly, a PyTorch library for spiking networks. Its LIF neuron differs from the chip's in two ways. It adds the input before testing the threshold, so a spike can come in the same step as the input that caused it. It also shrinks the input by the leak, computing v += (x − v)/τ, so at τ = 4 the neuron receives a quarter of each input.

A network trained with the library neuron and then run on the chip would see different spike timing and a different input scale in every layer, and the error grows with depth. That motivates HardwareLIFNode, a PyTorch neuron that runs the chip's order exactly: fire, reset, leak, integrate, with the input added at full size. It is the only neuron the tool builds, so the training network and the deployed network follow the same rule.

2.3The leak is a shift

The chip stores the leak as a shift amount k and subtracts v >> k each step, which equals v / 2k rounded down. So τ can only be a power of two: 2, 4, 8, 16 and so on. A network trained with τ = 3 has nothing on the chip to run it with.

Letting training learn τ is still useful, which motivates learning log2(τ) and rounding it during training. The forward pass always uses a power of two, and the gradient still reaches the parameter through the technique in section 2.5. A search samples the starting τ from {2, 4, 8, 16}.

The rounding down also matters. When the potential is smaller than 2k in the chip's integer units, the leak rounds to zero and the potential does not decay at all. Training rounds the leak the same way.

Why weight decay no longer touches τ

Weight decay is a training penalty that pulls every parameter toward zero. It used to apply to τ as well. Three otherwise identical runs that started at τ = 8 and trained for 300 epochs (passes through the training data) ended with τ near 5.5, 3 and 0 as the weight decay rose from 0.0001 to 0.01. The search was setting τ through weight decay without meaning to, which motivated applying weight decay only to connection weights.

2.4Keeping the threshold in range

The chip stores θ on the same integer grid as the weights, as a whole number from 1 to 32,767, so θ must lie in (0, 1]. A larger θ cannot be stored, and a θ of zero or below makes the neuron fire on every step.

A threshold that training learns freely can wander out of that range, which motivates writing θ = sigmoid(raw). A sigmoid always returns a value between 0 and 1, so no update can push θ out. The result is then rounded to the grid. Folding batch normalization can still shift θ later (section 4.3), so the deployment check reads the folded value directly.

2.5Training through a spike

Gradient descent changes each weight in proportion to how much the loss would change if the weight moved slightly. A spike gets in the way. It is a step: 0 below θ and 1 above, so its slope is zero everywhere except at θ, where it is undefined. Backpropagation multiplies those slopes together, so no gradient would reach any weight below a spiking layer.

The forward pass has to keep the real step, because that is what the chip computes, which motivates changing only the backward pass. It uses the slope of a smooth curve shaped like the step (here an arctangent). A neuron that came close to firing gets a large gradient, and one far from θ gets almost none. This is called a surrogate gradient. The same idea, passing a gradient through a rounding step as if it were not there, is the straight-through estimator that section 4.4 uses for weights.

2.6The code

The forward pass below combines sections 2.1 to 2.5.

Source: snnsearch/neuron.py
snnsearch/neuron.pyHardwareLIFNode.single_step_forward
def single_step_forward(self, x: "torch.Tensor"):
    self.v_float_to_tensor(x)
    v_reset = 0.0 if self.v_reset is None else float(self.v_reset)
    v_th = self.v_threshold
    # During inline-fold QAT (ConvBNFoldQuant, threshold mode) the folded
    # bias b' is delivered here each step instead of into the conv.
    #
    # It has to be applied the way the chip applies it. Adding b' to the
    # input and lowering the threshold by b' are NOT the same operation
    # once tau > 1. A bias arrives every timestep and accumulates against
    # the leak: the membrane offset after t steps without a spike is
    #     d_t = b' * tau * (1 - (1 - 1/tau)^t)   ->  b' * tau
    # while a threshold shift is worth b' once and never compounds. At
    # tau=63 a bias of 0.01*theta already moves the membrane by 0.63.
    # export_deployed writes theta - b', so QAT must do the same or the
    # trained network is not the deployed one. Measured on
    # results/probe.pth the two forms disagree on 9-35% of
    # channel-timesteps; see tools/analysis/fold_bias_equivalence.py.
    fb = getattr(self, "_fold_bias", None)
    if fb is not None:
        shape = [1, fb.shape[0]] + [1] * (x.dim() - 2)   # broadcast over (N,C,...)
        fb_b = fb.reshape(*shape)
        if getattr(self, "_fold_bias_form", "threshold") == "threshold":
            # quantize AFTER the shift, so the value is the one the chip
            # stores, including saturation if the band was not enforced.
            v_th = fake_quantize_threshold(v_th - fb_b)
        else:
            x = x + fb_b            # legacy form, kept for A/B only
    # 1. fire on the membrane carried in from the previous timestep.
    #    The chip compares v > theta (strictly greater); one LSB of the
    #    integer grid is W_DELTA, so subtracting it reproduces `>` from
    #    the surrogate's `>=` without breaking the gradient.
    spike = self.surrogate_function(self.v - v_th - W_DELTA)
    # 2. hard reset
    spike_d = spike.detach() if self.detach_reset else spike
    self.v = v_reset * spike_d + (1.0 - spike_d) * self.v
    # 3. leak toward v_reset, by INTEGER DIVISION on the chip's grid.
    #
    #    The membrane is an integer register, so the chip cannot subtract
    #    a fractional leak. It computes floor(v_int / tau) and subtracts
    #    that. A float division is close but never equal, and the error
    #    accumulates over T steps and compounds through depth.
    #
    #    Flooring here also CLOSES the grid. Every weight is an exact
    #    multiple of W_DELTA after fake quantization, spikes are 0 or 1,
    #    and v starts at rest, so v stays on the grid as long as nothing
    #    ever subtracts an off-grid amount. The float leak was the one
    #    operation that did. With it floored, the simulated membrane is
    #    the deployed membrane, step for step.
    #
    #    Note the dead zone this creates: when |v - v_reset| < tau LSBs
    #    the leak floors to zero and the membrane does not decay at all.
    #    That is real hardware behaviour, not an artifact, and it makes
    #    the large-tau end of HW_TAU_CHOICES behave very differently from
    #    what a continuous model predicts.
    #
    #    floor has zero gradient everywhere it is defined, so the
    #    straight-through estimator passes the float leak's gradient, the
    #    same way fake_quantize_weight does for the weights.
    #    Behind an AvgPool2d(p) the membrane moves in steps of
    #    W_DELTA / p^2, and the deployed network keeps it in those finer
    #    units (see hs_export.py). leak_grid lets evaluation floor on
    #    that grid, which is what the chip does. Training leaves it at
    #    W_DELTA.
    leak = (self.v - v_reset) / self.hw_tau
    if getattr(self, "integer_leak", True):
        grid = getattr(self, "leak_grid", W_DELTA)
        leak = _ste(torch.floor(leak / grid) * grid, leak)
    self.v = self.v - leak
    # 4. integrate this timestep's input, undecayed
    self.v = self.v + x
    return spike
  • self.v holds one potential per neuron in the layer, so one call updates the whole layer.
  • Subtracting W_DELTA, one step of the integer grid, turns the library's "greater or equal" test into the chip's "strictly greater".
  • leak_grid is the integer step of this layer's membrane. Behind an average pool the membrane moves in finer steps (section 4.1), and the leak rounds down on that finer grid, as the chip does.
  • The _fold_bias block applies batch normalization's bias as a threshold shift, when the network deploys its bias that way (section 4.3).
