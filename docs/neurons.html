Chapter 2 · Spiking Neurons

The leaky bucket,
now with equations

One small machine, repeated tens of thousands of times: the Leaky Integrate-and-Fire (LIF) neuron. Build it from scratch, drive a full simulator, then meet the three ways the chip's neuron differs from the textbook's — each of which silently changes what the network computes.

2.1Anatomy of a spiking neuron

A LIF neuron owns exactly one number and three settings:

  • v — the membrane potential. The water level in the bucket. Starts at 0. This is the neuron's entire memory.
  • τ (tau) — the leak constant. Each timestep, the level decays toward rest by a factor: v ← v − v/τ. τ=2 keeps half each step (fast forgetting); τ=63 keeps ~98.4% (long memory).
  • θ (theta) — the firing threshold. When v exceeds θ, the neuron emits a spike.
  • v_reset — where v lands after firing. Here always 0, and the reset is a hard reset: after a spike the bucket is emptied completely, regardless of how far above θ it was.

Each timestep, input arrives as one number x:

  • x = Σ (weight × spike) over all upstream neurons that fired this step.
  • Negative weights are inhibitory — they scoop water out of the bucket.

And the deployed neuron has a twist: the chip performs its steps in this exact order, quoted straight from the code —

Practice2.py · HardwareLIFNode docstring§5
#   spike = v > theta ;  v = reset ;  v -= (v - v_reset)/tau ;  v += x
#
# So every spiking layer adds one timestep of latency, which is exactly
# why the conversion script runs `num_layers` extra zero-input steps to
# flush the pipeline.

In words, each timestep the hardware neuron does:

  1. Fire — on yesterday's water level. Compare the v carried in from the previous timestep against θ (strictly greater). If v > θ: output a spike now.
  2. Reset. If it fired, empty the bucket to v_reset (0).
  3. Leak. Decay toward rest: v ← v − (v − v_reset)/τ. With integer τ this is one shift-and-subtract on chip — dirt cheap.
  4. Integrate. Pour in this timestep's input, at full strength: v ← v + x.
What step 1 implies
  • Input at time t can cause a spike at t+1, at the earliest. The neuron is a one-tick delay line.
  • Stack 5 spiking layers → the answer lags the input by 5 ticks.
  • That lag is the "pipeline flush" chapter 5 animates.

2.3Two neurons walk into a timestep: textbook vs. chip

The obvious approach — train with SpikingJelly's standard neuron, convert to the chip's afterward — is what earlier versions did. It got ripped out. The two neurons disagree in three ways, each quietly changing the network:

SpikingJelly LIFNode charge → fire
  1. Add input (decayed: v += (x − v)/τ)
  2. Compare v ≥ θ → maybe spike this same step
  3. Reset if spiked

Input at time t can cause a spike at time t. No inter-layer latency.

HardwareLIFNode (the chip) fire → reset → leak → integrate
  1. Compare carried-over v > θ → maybe spike
  2. Reset if spiked, then leak
  3. Add input raw and undecayed (v += x)

Input at t spikes at t+1 at the earliest. Every layer = one tick of delay.

The three differences, named:

  • Latency structure. Same weights, different spike timing — and the deeper the network, the worse the accumulated mismatch.
  • Decayed vs. raw input. SpikingJelly's default folds the input into the leak (decay_input=True, so a τ=4 neuron only feels ¼ of each input). The chip adds the raw weighted input. Same τ, different effective input strength.
  • Continuous vs. integer τ. Next section.

2.4The leak is an integer (and pretending otherwise fooled a whole search)

On HiAER-Spike, τ deploys into an integer register: leak = round(τ). That sounds small. It isn't:

  • The trap: an earlier search tuned τ continuously in [1.5, 2.5] and found a lovely τ↔accuracy correlation…
  • The problem: every value in that range deploys as leak=2. The search was optimizing a knob that does not exist on the chip.
  • The fix (from the file's comment):
Practice2.py · search space§10
# tau was suggest_float(1.5, 2.5). On chip the leak register is an
# integer and the converter's convention is leak = round(tau), so EVERY
# value in that interval deployed as leak=2: the search was resolving a
# difference that does not survive conversion, and the float metric was
# rewarding it.

HW_TAU_CHOICES = [2, 3, 4, 6, 8, 16, 32, 63]   # the leak values worth searching

Why that spacing?

  • Small end — coarse on purpose: τ=2 keeps 50%/step, τ=3 keeps 67% — genuinely different networks one integer apart.
  • Large end — nearly flat: τ=63 vs 64 is invisible; 63 matches a known-working DVS conversion.
  • Learned τ stays honest: with trainable_tau=True the rounding happens inside the forward pass (straight-through gradient), so even a learned τ is always the exact integer the chip will use.

2.5The threshold lives in (0, 1] — by construction, not by hope

The chip stores θ as the integer int(θ / w_delta) where w_delta = 1/32767 (chapter 4 explains where that grid comes from). Three danger zones, and how the code walls each off:

  • θ > 1.0 → the integer overflows the 16-bit field. So θ = 1.0 (which lands exactly on 32767) is the ceiling.
  • θ ≤ 0 → v > θ is true every step: the neuron fires unconditionally, forever, regardless of input. A network containing one such neuron is garbage that still runs — the worst kind of bug.
  • Learned θ wandering out of range → when trainable_threshold=True, θ is not the raw parameter. The code stores an unconstrained number raw_threshold and computes θ = sigmoid(raw), which mathematically cannot leave (0, 1). The optimizer can push raw anywhere it likes; θ stays legal.
One elegant detail

The chip compares strictly (v > θ); the training surrogate computes "≥". Reconciliation: fire on v − θ − w_delta ≥ 0 — subtracting exactly one grid step turns ≥ into > without breaking gradients.

2.6The trick that makes any of this trainable: surrogate gradients

Training = nudging weights downhill on the loss. "Downhill" comes from derivatives. Spikes break that:

  • The problem: a spike is a step function — below θ gives 0, above gives 1. Its derivative is zero everywhere (infinite at the exact threshold). Zero gradient = zero learning signal. Taken literally, SNNs can't be trained by backpropagation.
  • The workaround — a principled lie: on the forward pass, use the true hard step (real 0/1 spikes). On the backward pass only, pretend it had been a smooth S-curve and hand back that curve's derivative — a gentle bump peaked at the threshold.
  • This code's choice: SpikingJelly's surrogate.ATan(), bump = α/2 · 1/(1 + (π/2·α·x)²).

2.7The real forward pass, annotated

Here is the actual heart of HardwareLIFNode, with everything above visible in ~15 lines:

Practice2.py · HardwareLIFNode.single_step_forward§5
def single_step_forward(self, x: "torch.Tensor"):
    self.v_float_to_tensor(x)
    v_reset = 0.0 if self.v_reset is None else float(self.v_reset)
    v_th = self.v_threshold                     # already on the chip's grid

    # (QAT detail, ch.4: a folded BatchNorm bias may be delivered here,
    #  which is identical to a per-channel threshold shift on chip)
    fb = getattr(self, "_fold_bias", None)
    if fb is not None:
        shape = [1, fb.shape[0]] + [1] * (x.dim() - 2)
        x = x + fb.reshape(*shape)

    # 1. fire on the membrane carried in from the PREVIOUS timestep.
    #    − W_DELTA turns the surrogate's ">=" into the chip's strict ">"
    spike = self.surrogate_function(self.v - v_th - W_DELTA)
    # 2. hard reset
    spike_d = spike.detach() if self.detach_reset else spike
    self.v = v_reset * spike_d + (1.0 - spike_d) * self.v
    # 3. integer leak toward v_reset
    self.v = self.v - (self.v - v_reset) / self.hw_tau
    # 4. integrate this timestep's input, undecayed
    self.v = self.v + x
    return spike

Line-by-line notes for the non-PyTorch reader:

  • self.v is a whole tensor of membrane levels — one per neuron in the layer — updated in parallel. The "one neuron" story runs thousands-wide.
  • surrogate_function(...) returns hard 0/1 spikes forward and the ATan bump backward (§2.6).
  • spike.detach() in the reset (with detach_reset=True) stops gradients flowing through the reset path — a standard stabilizer, so learning signal comes from the spike itself, not from bookkeeping.
  • self.hw_tau is a property: for a fixed τ it's the stored integer; for a learned τ it clamps to [2,128] and rounds with a straight-through gradient, so the loss always sees the true integer leak.
  • The _fold_bias block is dormant until quantization-aware training begins — it's how a folded BatchNorm's bias reaches the neuron. Full story in chapter 4.
The design philosophy, in one quote

From build_neuron: "There is deliberately no 'train with a nice neuron, convert to the hardware one later' path any more. Every substitution of that kind … is a silent change to the network that only shows up after conversion, which is exactly the gap this search exists to close." One neuron type (LIF), one implementation, trained exactly as deployed. Anything else raises NotImplementedError.
