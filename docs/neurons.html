The neuron

Section 1.1 listed four properties of the neuron that HiAER-Spike fixes: the order of its update, the integer leak register, the integer threshold, and the resulting one-timestep delay per layer. This page builds a neuron in PyTorch that matches all four, and covers the method that makes a binary spike trainable at all.

2.1The update rule

A LIF neuron stores one value, the membrane potential v. Its behaviour is set by three parameters:

τ
The leak constant. Each timestep v moves toward rest by v/τ. At τ=2 half the potential remains after one step; at τ=63 about 98.4% remains.
θ
The firing threshold. The neuron emits a spike when v exceeds it.
v_reset
The value v takes after firing, fixed at 0 here. The reset is unconditional, so any overshoot above θ is discarded.

Input arrives once per timestep as a single number: the sum of connection weights over the upstream neurons that fired. Weights may be negative, which lowers the potential.

The chip performs the four operations in a fixed order, recorded in the code as:

Practice2.py · HardwareLIFNode docstring§5
#   spike = v > theta ;  v = reset ;  v -= (v - v_reset)/tau ;  v += x
  1. Fire Compare the potential carried in from the previous timestep against θ, using a strict inequality. Emit a spike if it is larger.
  2. Reset Set the potential to 0 if the neuron fired.
  3. Leak Decay the potential toward rest by v/τ.
  4. Integrate Add this timestep's input at full magnitude.

Firing happens before integration, so input arriving at timestep t can influence the output no earlier than t+1. A network of five spiking layers therefore produces its response five timesteps after the input that caused it. Section 5.4 uses this fact directly.

2.2Matching the chip's update order

The SNN library used here, SpikingJelly, provides a LIF neuron. Its update order differs from the chip's in two ways. It adds input before testing the threshold, so a spike can occur in the same timestep as the input that caused it. It also scales input by the leak, computing v += (x − v)/τ, so a neuron with τ=4 receives a quarter of each input.

Observation

Training with the library neuron and converting afterwards produces a network whose spike times and effective input scale both differ from what was trained. The error grows with depth, because each layer contributes its own timing offset.

Consequence

The substitution has to be removed. Training and deployment need to use one neuron, which means implementing the chip's update order directly rather than converting into it later.

In code

HardwareLIFNode implements fire, reset, leak, integrate in that order, with undecayed input. build_neuron returns it on every path and raises NotImplementedError for any other neuron type, so no alternative can be selected by accident.

2.3The leak is an integer

Section 1.1 noted that the chip holds the leak in an integer register. The converter writes round(τ) into it.

Observation

An earlier version of the search sampled τ as a continuous value between 1.5 and 2.5 and found a correlation between τ and accuracy. Every value in that interval rounds to 2, so all of those configurations deploy as the same network. The correlation described a coordinate the hardware cannot represent.

Consequence

τ has to be sampled from integers, and a learned τ has to be rounded inside the forward pass so that the loss responds to the value that will actually deploy. The useful integers are closely spaced at the low end, where consecutive values behave differently, and sparse at the high end, where they do not.

In code

HW_TAU_CHOICES = [2, 3, 4, 6, 8, 16, 32, 63] defines the sampled set. The hw_tau property clamps to the register range and rounds, passing the gradient through unchanged so the parameter remains trainable.

2.4Keeping the threshold representable

The chip stores the threshold as int(θ / w_delta) with w_delta = 1/32767. Two values of θ break that encoding. Above 1.0 the integer exceeds the field. At or below 0 the comparison v > θ is always true, and the neuron fires on every timestep regardless of input.

Observation

The project treats θ as a parameter worth learning per layer. An unconstrained parameter can take any real value during training, including values that cannot be encoded.

Consequence

The constraint has to be built into the parametrisation rather than checked afterwards, so that no optimiser step can produce an illegal threshold. A separate accessor is needed for deployment checks, because a clamp applied for numerical safety would hide an illegal value from the check that is supposed to catch it.

In code

The learned value is stored as raw_threshold and read as sigmoid(raw_threshold), which lies in (0, 1) by construction. fake_quantize_threshold then snaps it to the integer grid, and raw_v_threshold() exposes the unclamped value for the deployment report.

2.5Training through a binary spike

Gradient descent adjusts a weight using the derivative of the loss with respect to that weight. The spike function stands in the way: it outputs 0 below the threshold and 1 above it, so its derivative is zero everywhere it is defined and undefined at the threshold itself.

Observation

With a zero derivative at the spike, backpropagation delivers no gradient to any weight beneath it. Applied literally, the network cannot be trained by gradient descent.

Consequence

The forward pass has to keep the true binary spike, because that is what the chip computes. Only the backward pass can be altered. Substituting the derivative of a smooth function that approximates the step gives each neuron a gradient proportional to how close it came to firing.

In code

The neuron calls surrogate.ATan(), which returns a hard 0 or 1 forward and the derivative α/2 · 1/(1 + (π/2 · αx)²) backward. The same technique appears again in section 4.4 for weight rounding.

2.6The forward pass

The four decisions above appear together in about fifteen lines.

Practice2.py · HardwareLIFNode.single_step_forward§5
def single_step_forward(self, x: "torch.Tensor"):
    self.v_float_to_tensor(x)
    v_reset = 0.0 if self.v_reset is None else float(self.v_reset)
    v_th = self.v_threshold                     # already on the chip's grid

    fb = getattr(self, "_fold_bias", None)      # set during quantisation-aware training
    if fb is not None:
        shape = [1, fb.shape[0]] + [1] * (x.dim() - 2)
        x = x + fb.reshape(*shape)

    # 1. fire on the membrane carried in from the previous timestep.
    #    subtracting one grid step turns the surrogate's ">=" into the chip's ">"
    spike = self.surrogate_function(self.v - v_th - W_DELTA)
    # 2. hard reset
    spike_d = spike.detach() if self.detach_reset else spike
    self.v = v_reset * spike_d + (1.0 - spike_d) * self.v
    # 3. integer leak toward v_reset
    self.v = self.v - (self.v - v_reset) / self.hw_tau
    # 4. integrate this timestep's input, undecayed
    self.v = self.v + x
    return spike
  • self.v holds one potential per neuron in the layer, so the update runs across the whole layer at once.
  • Subtracting W_DELTA before the comparison reproduces the chip's strict inequality using a surrogate that tests for greater-or-equal.
  • spike.detach() in the reset keeps gradients from flowing through the reset path, which stabilises training.
  • self.hw_tau returns the stored integer, or the rounded learned value when τ is trainable.
  • The _fold_bias block is inactive during ordinary training. Section 4.5 describes what sets it.
