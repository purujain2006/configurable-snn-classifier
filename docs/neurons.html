The neuron

HiAER-Spike runs one kind of neuron, with a fixed update order, a leak that must be a power of two, and a threshold limited to (0, 1]. This page rebuilds that neuron for training, exactly, and explains how a network made of it can still learn.

2.1The update rule

Page A introduced the leaky integrate-and-fire neuron. This page covers the details that decide whether a trained network behaves the same way on the chip. The neuron stores one number, its membrane potential v, and three constants set its behavior.

τ
The leak. Each step v loses v/τ, rounded down. At τ = 2 half the potential remains after one step; at τ = 16, about 94% remains.
θ
The threshold. The neuron fires when v is strictly greater than θ.
reset value
The value v takes after firing, which is 0 here. Anything above θ is thrown away.

The input at each step is one number: the sum of the weights of the incoming connections whose source neuron fired. Weights can be negative, which lowers the potential. The chip performs four operations in a fixed order:

  1. Fire. Compare the potential carried in from the previous step against θ. Emit a spike if it is strictly greater.
  2. Reset. If the neuron fired, set the potential to 0.
  3. Leak. Subtract v/τ, rounded down.
  4. Integrate. Add this step's input at full size.

Because the neuron fires before it integrates, input arriving at step t can cause a spike no earlier than step t+1. A network with five spiking layers answers five steps after the input that caused the answer, which is why every clip ends with a few empty steps (section 5.3).

Work through three steps by hand

Start at v = 0 with τ = 4, θ = 1, and an input of 0.6 on every step.

  1. Step 1: 0 is below θ, so no spike. The leak leaves 0, and the input raises v to 0.6.
  2. Step 2: 0.6 is below θ. The leak removes 0.6 / 4 = 0.15, and the input raises v to 1.05.
  3. Step 3: 1.05 is above θ, so the neuron fires and resets to 0. The input raises v to 0.6 again.

The spike comes one step after the potential first passed 1. Each layer of a network adds one such step.

2.2Matching the chip's update order

The training code is built on SpikingJelly, a PyTorch library for spiking networks. Its LIF neuron differs from the chip's in two ways. It adds the input before testing the threshold, so a spike can come in the same step as the input that caused it. It also shrinks the input by the leak, computing v += (x − v)/τ, so at τ = 4 the neuron receives a quarter of each input.

A network trained with the library neuron and then run on the chip would see different spike timing and a different input scale in every layer, and the error grows with depth. That motivates a training neuron that runs the chip's order exactly: fire, reset, leak, integrate, with the input added at full size, the strict comparison against θ, and the leak rounded down on the chip's integer grid. It is the only neuron the tool builds, so the network that trains and the network that deploys follow the same rule, spike for spike.

2.3The leak is a shift

The chip stores the leak as a shift amount k and subtracts v >> k each step, which equals v / 2k rounded down. So τ can only be a power of two: 2, 4, 8, 16 and so on. A network trained with τ = 3 has nothing on the chip to run it with.

Letting training learn τ is still useful, which motivates learning log2(τ) and rounding it during training. The forward pass always uses a power of two, and the gradient still reaches the parameter through the technique in section 2.5. A search samples the starting τ from {2, 4, 8, 16}, and whether τ stays fixed, is learned once per layer, or is learned separately for each channel. The chip stores settings for every neuron, so a different τ in each channel costs nothing to deploy.

The rounding down also matters. When the potential is smaller than 2k in the chip's integer units, the leak rounds to zero and the potential does not decay at all. Training rounds the leak the same way. Behind an average pool the potential moves in finer steps (section 4.1), and there the leak rounds down on that finer grid, as the chip does.

Why weight decay leaves τ alone

Weight decay is a training penalty that pulls every parameter it applies to toward zero. Applied to τ, it shrinks the leak constant along with the weights, so the strength of weight decay ends up deciding how fast the neurons forget. In three otherwise identical runs of 300 epochs (passes through the training data) that started at τ = 8, τ ended near 5.5, 3 and 0 as weight decay rose from 0.0001 to 0.01. That motivates applying weight decay only to connection weights, so τ moves only when moving it helps the network.

2.4Keeping the threshold in range

The chip stores θ on the same integer grid as the weights, as a whole number from 1 to 32,767, so θ must lie in (0, 1]. A larger θ cannot be stored, and a θ of zero or below makes the neuron fire on every step.

A threshold that training learns freely can wander out of that range, which motivates writing θ = sigmoid(raw), where raw is the number the optimizer actually updates. A sigmoid always returns a value between 0 and 1, so no update can push θ out. The result is then rounded to the grid. Folding batch normalization can still shift θ later (section 4.3), so the deployment check reads the folded value directly.

2.5Training through a spike

A spike is a step: 0 below θ and 1 above, so its slope is zero everywhere except at θ, where it is undefined. Backpropagation multiplies slopes together layer by layer, so no gradient would reach any weight below a spiking layer (page A draws the problem).

The forward pass has to keep the real step, because that is what the chip computes, which motivates changing only the backward pass. It uses the slope of a smooth curve shaped like the step, here an arctangent. A neuron that came close to firing gets a large gradient, and one far from θ gets almost none. This is called a surrogate gradient. The same idea, passing a gradient through a rounding step as if it were not there, is the straight-through estimator that section 4.4 uses for weights.

Neurons close to their threshold receive most of the gradient, which matches the intuition that a small weight change there would have altered the spike.

Rounding the leak down has the same problem as the spike: its slope is zero wherever it is defined. Training passes the gradient of the unrounded leak through it with the straight-through estimator, so the forward pass stays exact and learning still works.
