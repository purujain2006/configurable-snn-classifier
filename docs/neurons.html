The chip's neuron

HiAER-Spike runs one kind of neuron, with a fixed update order, a leak that must be a power of two, and a threshold limited to (0, 1]. This page shows how training rebuilds that neuron exactly, so the chip produces the same spikes the trained network did.

F.1Why the neuron needs its own page

Page A introduced the leaky integrate-and-fire neuron and the order the chip runs it in, which is fire, reset, leak, integrate. A trained network only works on the chip if training uses that exact neuron, down to the rounding. This page covers the three places where the usual training tools and the chip disagree. They are the order of the four steps, the leak, and the range of the threshold.

F.2Matching the chip's update order

The training code is built on SpikingJelly, a PyTorch library for spiking networks. Its LIF neuron differs from the chip's in two ways. It adds the input before testing the threshold, so a spike can come in the same step as the input that caused it. It also shrinks the input by the leak, computing v += (x − v)/τ, so at τ = 4 the neuron receives a quarter of each input.

A network trained with the library neuron and then run on the chip would see different spike timing and a different input scale in every layer, and the error grows with depth. So the tool trains with its own neuron, which runs the chip's order exactly. It fires, resets, leaks and integrates, with the input added at full size, the strict comparison against θ, and the leak rounded down on the chip's integer grid. It is the only neuron the tool builds, so training and the chip use the same rule and produce the same spikes.

F.3The leak is a shift

The chip stores the leak as a shift amount k and subtracts v >> k each step. That is a bit shift, and it equals v / 2k rounded down. So τ can only be a power of two: 2, 4, 8, 16 and so on. A network trained with τ = 3 has nothing on the chip to run it with.

Letting training learn τ is still useful, which motivates learning log2(τ) and rounding it during training. The forward pass always uses a power of two, and the gradient still reaches the parameter through a surrogate, the method page A uses for spikes. A search samples the starting τ from {2, 4, 8, 16}, and whether τ stays fixed, is learned once per layer, or is learned separately for each channel. The chip stores settings for every neuron, so a different τ in each channel costs nothing to deploy.

The rounding down also matters. When the potential is smaller than 2k in the chip's integer units, the leak rounds to zero and the potential does not decay at all. Training rounds the leak the same way. Behind an average pool the potential moves in finer steps (page G), and there the leak rounds down on that finer grid, as the chip does.

Why weight decay leaves τ alone

Weight decay is a training penalty that pulls every parameter it applies to toward zero. Applied to τ, it shrinks the leak constant along with the weights, so the strength of weight decay ends up deciding how fast the neurons forget. In three otherwise identical runs of 300 epochs (passes through the training data) that started at τ = 8, τ ended near 5.5, 3 and 0 as weight decay rose from 0.0001 to 0.01. So the tool applies weight decay only to connection weights, so τ moves only when moving it helps the network.

In the search records

tau = 4 is the starting leak and tau_mode = fixed keeps it there. With layer or channel, training learns it, always as a power of two. deployed_tau = 4,4,4,4,4 is what each spiking layer actually runs with on the chip, so it is where a learned τ shows up.

F.4Keeping the threshold in range

The chip stores θ on the same integer grid as the weights, as a whole number from 1 to 32,767, so θ must lie in (0, 1]. A larger θ cannot be stored, and a θ of zero or below makes the neuron fire on every step.

A threshold that training learns freely can wander out of that range, so the tool writes θ = sigmoid(raw), where raw is the number the optimizer actually updates. A sigmoid always returns a value between 0 and 1, so no update can push θ out. The result is then rounded to the grid. Folding batch normalization can still shift θ later (page G), so the deployment check reads the folded value directly.
