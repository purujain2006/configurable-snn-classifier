B.1An event camera

Why this exists

An ordinary camera sends every pixel of every frame, even when nothing in the scene moves, which wastes data and power, and fast motion between frames blurs or goes missing. The eye's retina mostly reports change. Event cameras copy that idea, and their output already looks like spikes, which suits a spiking chip.

An ordinary camera takes whole pictures at a fixed rate. An event camera, also called a dynamic vision sensor or DVS, has no frames at all. Each pixel watches its own brightness and reports an event the moment the brightness changes enough: where it happened, when (to the microsecond), and which way it went, brighter or darker. A still scene produces almost nothing, and a moving hand produces a stream of events along its edges.

That makes event cameras a natural partner for spiking networks: the data already arrives as spikes, and it costs nothing where nothing moves.

ANIMATION A simulated 128 × 128 event camera Blue events mean a pixel got brighter, orange events mean it got darker. Events fade after a few milliseconds so the motion is visible. The gesture chosen here is used throughout this page.

Only the moving arm and hand make events. The body, the background and the arm's still upper half are invisible to the sensor, because nothing about them changes.

The dataset is DVS128 Gesture: 29 people performing 11 gestures in front of a 128 × 128 event camera, under several lighting conditions. The gestures are hand clap, right and left hand wave, right and left arm circles in each direction, arm roll, air drums, air guitar, and a class for other movements. There are 1,464 recordings: 1,176 from 23 people for training and 288 from 6 other people for testing.

B.2From events to frames

A spiking network runs in timesteps, so each recording is cut into T slices holding the same number of events, and each slice becomes one frame with two channels: one for brighter events and one for darker events. With one bit per pixel, a pixel is 1 if any event landed on it during the slice. More slices give finer timing but more steps to run, and every step costs time on the chip.

With few frames, each frame smears a long stretch of motion into one picture. With many, each frame holds only a few events and the network has more steps to integrate them over.

Making the picture smaller

The chip receives its input on input lines called axons, and it has 16,000 of them. A 128 × 128 frame with two channels needs 32,768, so frames are shrunk first: each pixel of the small frame covers a block of the large one, and is 1 if any event landed anywhere in that block. The largest square that fits is 89 × 89, and the search tries sizes from 24 to 88. Smaller frames are cheaper but lose detail. With more than one bit per pixel, each pixel needs several axons (page E), which lowers the largest size that fits.

INTERACTIVE Shrinking a frame to fit the chip's input Left: one frame at the camera's 128 × 128. Right: the same frame at the chosen size. The bar shows how many of the chip's 16,000 input axons it uses.
Why shrink with "any event" instead of an average?

Averaging neighboring pixels is the usual way to shrink a picture, but it treats sparse events badly. A lone event in a block becomes a small fraction, and a fraction cannot be sent as a spike. Marking a small pixel as 1 whenever any event landed in its block keeps every event. Click the left frame to place events and compare the two rules.

The range of frame sizes a search tries comes from the dataset: from about a quarter of the largest size up to the camera's own size or the largest square that fits in 16,000 axons, whichever is smaller. For DVS128 Gesture that is 24 × 24 to 88 × 88, in steps of 8.

B.3Training, validation and test

Why this exists

A network graded on the clips it trained on can score close to 100% by memorizing them, which says nothing about new people. A fair score needs clips the network never saw. Choosing among many networks by their scores also bends the choice toward the clips used to choose, so the final grade needs one more set, kept untouched until the end.

The data is split three ways, and each part has one job.

Training set
The examples the network learns from. Its weights are adjusted to fit these.
Validation set
Examples held back from training and used to choose between networks. Every trial in a search is scored on it. Because the search keeps whichever network does best here, the winner's validation score is a little optimistic.
Test set
Examples nobody looks at until the very end, scored once on the final network. It is the honest estimate of how the network does on new data.

How the split is made matters as much as its size. The test set is 6 people who never appear in training, so the real question is how well a network handles people it has never seen. The validation set asks the same question by holding out whole people too: four of the 23 training people, 216 clips, are set aside, and the network trains on the other 19.

Every score in the records is a fraction of clips. For the example network, hw_val_accuracy = 0.745 means it got 161 of the 216 validation clips right; hw stands for hardware, because the score belongs to the network as written out for the chip. Trials are ranked by val_accuracy: the same score for a network that can run on the chip, and 0 for one that cannot. The test score, measured once at the very end, is hw_test_accuracy: 0.854 for the network the search finally picked (page H), or 246 of the 288 test clips.

A network can learn its training examples too well. It memorizes details that belong to those 19 people, such as how one person holds their arm or where another stands, instead of what makes a wave a wave. The sign is a gap between accuracy on the training set and accuracy on the validation set.

The usual remedies are more varied data (augmentation, below), regularization that makes memorizing harder (dropout, which silences random units during training, weight decay and label smoothing, all on page D), smaller networks, and not training past the point where the gap opens. This gap, not the chip, is what holds accuracy back on this task.

B.5How much to trust one number

The validation set has 216 clips, so each clip is worth 0.46 percentage points, and luck in which clips happen to be hard moves the score. Take a network whose true accuracy on new people is fixed, and score it on many different validation sets of the same size: the measured scores spread out around the truth.

Two networks a few points apart on 216 clips may be equally good. That is why a search retrains its best few networks with new random starting weights before picking one, and why the test set is used only once, at the end.

B.6Giving every person a turn

Why this exists

The four validation people are one draw out of 23. If they happen to be hard to read, every network's validation score comes out low, and if they happen to be easy, it comes out high. Comparing two networks on the same four people is still fair, but the score says less about new people than it seems to.

K-fold cross-validation takes that luck out by giving every training person a turn as validation. The 23 training people are dealt into k groups, called folds, with about the same number of clips in each. The network is trained k times from scratch. Each time, one fold is held out for validation and the network trains on the people in the other folds. After k runs every person has been held out exactly once, and the network's score is the average of the k validation scores.

The average comes with a standard error, which says how far the average could move by chance. It is the spread of the k scores divided by the square root of k. Two networks whose averages are closer than about two standard errors are a tie.

INTERACTIVE Five folds of 23 people Each figure is one training person, labeled with the fold it belongs to. Press play to train once per fold. The highlighted fold is the validation set for that run. Below, each bar is one run's validation score.

The people and their scores are made up, with the same pattern as the real data: one fold, like the usual four validation people, is harder than the rest. Its score on its own sits well below the average over all five folds.

On DVS128 Gesture the usual four validation people are harder than average. Three of the four score below the test average for every network trained so far, which is one reason validation reads about 6 points below test (H.3).

Cross-validation costs k full training runs per network. With 5 folds of 300 epochs, one network takes as long as five long runs. So the tool uses it only to choose between a few finished networks, never inside the search, and fold runs never touch the test set.

In the tool--folds 5folds.json

Adding --folds 5 to a single run trains the five folds one after another, each in its own folder. Then folds.json lists every fold's validation people and score, the average with its standard error, and the score over every clip at once. Adding --fold 2 trains only fold 2, so the folds can run on different GPUs at the same time.

B.7Data augmentation

Augmentation makes new training examples out of old ones by changing them in ways that do not change the label. A wave moved a few pixels to the left is still a wave. The network sees a slightly different version of every clip each epoch, so memorizing individual clips stops paying off.

Shift
Move the whole clip by up to a set fraction of the frame, filling the uncovered edge with nothing.
Cutout
Blank out one square, so the network cannot depend on any single region.
Event drop
Delete each event with some probability, as if the sensor were less sensitive.

Each change is drawn once per clip and applied to every frame of that clip alike, so the motion inside the clip stays intact. Augmentation happens only during training: validation, test and the chip always see clips exactly as recorded.

INTERACTIVE One clip, augmented five ways Each picture shows three consecutive frames of the clip. The first is the original; the others are random draws with the strengths set here.

Every changed clip is still made of whole event values the chip could receive, so augmentation never teaches the network something the chip could not show it.

In the search recordsuse_augmentaug_shiftaug_cutoutaug_dropaug_flip

use_augment switches augmentation on or off for a trial. When it is on, aug_shift = 0.1 moves each clip by up to a tenth of the frame, aug_cutout = 0.2 blanks a square up to a fifth of the frame's side, and aug_drop = 0.1 deletes about one event in ten. aug_flip mirrors clips, and only when the dataset says a mirrored clip keeps its label, which DVS128 Gesture does not. The sliders above use the same three strengths.

Why no mirror flips

Flipping left to right is the most common augmentation for photographs, but here it changes the answer: a mirrored right-hand wave is a left-hand wave, and a clockwise arm circle becomes counter-clockwise. So flips are switched off for this dataset.

Augmentation makes the training task harder, so it needs longer training to pay off. Judged after a short run it can look as if it hurts, which is why the strength of each change is searched rather than fixed.

In short

An event camera reports changes, not pictures. Each recording is cut into T frames with equal numbers of events and shrunk to fit the chip's 16,000 input axons. Training data teaches, validation data chooses, and test data is scored once at the end; all three are split by person, because the real question is how a network handles people it has never seen. Small validation sets are noisy, and the gap between training and validation accuracy is the overfitting that augmentation and regularization fight.
