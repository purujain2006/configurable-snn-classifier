Data, testing and augmentation

Where the training examples come from, how a stream of camera events becomes something a network can read, how the data is split so that a score means something, and how augmentation stretches a small dataset further.

B.1An event camera

An ordinary camera takes whole pictures at a fixed rate. An event camera, also called a dynamic vision sensor or DVS, has no frames at all. Each pixel watches its own brightness and reports an event the moment the brightness changes enough: where it happened, when (to the microsecond), and which way it went, brighter or darker. A still scene produces almost nothing, and a moving hand produces a stream of events along its edges.

That makes event cameras a natural partner for spiking networks: the data already arrives as spikes, and it costs nothing where nothing moves.

ANIMATION A simulated 128 × 128 event camera Amber events mean a pixel got brighter, rust events mean it got darker. Events fade after a few milliseconds so the motion is visible. The gesture chosen here is used throughout this page.

Only the moving arm and hand make events. The body, the background and the arm's still upper half are invisible to the sensor, because nothing about them changes.

The dataset is DVS128 Gesture: 29 people performing 11 gestures in front of a 128 × 128 event camera, under several lighting conditions. The gestures are hand clap, right and left hand wave, right and left arm circles in each direction, arm roll, air drums, air guitar, and a class for other movements. There are 1,464 recordings: 1,176 from 23 people for training and 288 from 6 other people for testing.

B.2From events to frames

A spiking network runs in timesteps, so each recording is cut into T slices holding the same number of events, and each slice becomes one frame with two channels: one for brighter events and one for darker events. With one bit per pixel, a pixel is 1 if any event landed on it during the slice. More slices give finer timing but more steps to run, and every step costs time on the chip.

With few frames, each frame smears a long stretch of motion into one picture. With many, each frame holds only a few events and the network has more steps to integrate them over.

Making the picture smaller

The chip receives its input on input lines called axons, and it has 16,000 of them. A 128 × 128 frame with two channels needs 32,768, so frames are shrunk first: each pixel of the small frame covers a block of the large one, and is 1 if any event landed anywhere in that block. The largest square that fits is 89 × 89, and the search tries sizes from 24 to 88. Smaller frames are cheaper but lose detail. With more than one bit per pixel, each pixel needs several axons (page E), which lowers the largest size that fits.

B.3Training, validation and test

The data is split three ways, and each part has one job.

Training set
The examples the network learns from. Its weights are adjusted to fit these.
Validation set
Examples held back from training and used to choose between networks. Every trial in a search is scored on it. Because the search keeps whichever network does best here, the winner's validation score is a little optimistic.
Test set
Examples nobody looks at until the very end, scored once on the final network. It is the honest estimate of how the network does on new data.

How the split is made matters as much as its size. The test set is 6 people who never appear in training, so the real question is how well a network handles people it has never seen. The validation set asks the same question by holding out whole people too: four of the 23 training people, 216 clips, are set aside, and the network trains on the other 19.

B.4Overfitting

A network can learn its training examples too well. It memorises details that belong to those 19 people, such as how one person holds their arm or where another stands, instead of what makes a wave a wave. The sign is a gap between accuracy on the training set and accuracy on the validation set.

The usual remedies are more varied data (augmentation, below), regularization that makes memorising harder (dropout, weight decay and label smoothing, all on page D), smaller networks, and not training past the point where the gap opens. This gap, not the chip, is what holds accuracy back on this task.

B.5How much to trust one number

The validation set has 216 clips, so each clip is worth 0.46 percentage points, and luck in which clips happen to be hard moves the score. Imagine a network whose true accuracy on new people is fixed, and score it on many different validation sets of the same size: the measured scores spread out around the truth.

Two networks a few points apart on 216 clips may be equally good. That is why a search retrains its best few networks with new random starting weights before picking one, and why the test set is used only once, at the end.

B.6Data augmentation

Augmentation makes new training examples out of old ones by changing them in ways that do not change the label. A wave moved a few pixels to the left is still a wave. The network sees a slightly different version of every clip each epoch, so memorising individual clips stops paying off.

Shift
Move the whole clip by up to a set fraction of the frame, filling the uncovered edge with nothing.
Cutout
Blank out one square, so the network cannot depend on any single region.
Event drop
Delete each event with some probability, as if the sensor were less sensitive.

Each change is drawn once per clip and applied to every frame of that clip alike, so the motion inside the clip stays intact. Augmentation happens only during training: validation, test and the chip always see clips exactly as recorded.

Why no mirror flips

Flipping left to right is the most common augmentation for photographs, but here it changes the answer: a mirrored right-hand wave is a left-hand wave, and a clockwise arm circle becomes counter-clockwise. So flips are switched off for this dataset.

Augmentation makes the training task harder, so it needs longer training to pay off. Judged after a short run it can look as if it hurts, which is why the strength of each change is searched rather than fixed.

In short

An event camera reports changes, not pictures. Each recording is cut into T frames with equal numbers of events and shrunk to fit the chip's 16,000 input axons. Training data teaches, validation data chooses, and test data is scored once at the end; all three are split by person, because the real question is how a network handles people it has never seen. Small validation sets are noisy, and the gap between training and validation accuracy is the overfitting that augmentation and regularization fight.
