The architecture

The goal in section 1.6 is to search over network designs. A search can only vary what the program treats as data, and it can only reject a design cheaply if the layer shapes are known before anything is built. This page covers how a configuration is described, how its shapes are derived, and how its size on chip is counted.

3.1The network as configuration

Observation

Research code usually hardcodes its architecture. Changing the depth or the kernel size then means editing the model class, which a search process cannot do.

Consequence

Every property the search may vary has to live in a data structure that can be constructed and compared. Properties that affect the shape of the network should be separated from properties that affect only training, so the feasibility check can run without knowing the optimiser.

In code

Seven dataclasses hold the shape-determining settings, and an eighth, TrainSpec, holds the optimization recipe. A dataclass is simply a Python structure of named fields with types and defaults.

DataclassHoldsFields, with defaults
InputSpecThe input tensorC=2 polarity channels, H=W=128 sensor size, T=16 timesteps, resize_to=0, batch N=16
ConvLayerSpecOne convolutionout_channels, kernel_size, stride, padding, dilation, pool, and optional per-layer tau and v_threshold
EncoderSpecThe convolution stackUniform fields (depth, channels, kernel_size) or a per-layer layers_json, plus bias and norm
OutputSpecThe classifier widthnum_classes=11
DownsampleSpecResolution reductionmode of stride or pool, pool_type, pool kernel and stride
HeadSpecThe classifier headfinal_reduction of flatten or gap, fc_widths, dropout_rate
NeuronSpecThe neuron of page 2tau as an integer, v_threshold, v_reset, trainable_tau, trainable_threshold

Reaching the fields from a command line

Each group is exposed as a flag that accepts key=value pairs. One function, fill_from_kv, reads the dataclass's own field list to decide which keys are valid and what type each value should become. Adding a field to a dataclass therefore adds its command-line option without further work.

def fill_from_kv(schema_cls, values: list[str]):
    obj = schema_cls()                                    # start from defaults
    field_types = {f.name: f.type for f in fields(schema_cls)}
    aliases = _FIELD_ALIASES.get(schema_cls.__name__, {})
    for item in values:
        if "=" not in item:
            raise ValueError(f"Expected key=value (e.g. 'N=16'), got: {item!r}")
        key, raw_value = item.split("=", 1)
        if key in aliases:
            key, raw_value = aliases[key](raw_value)
        if key not in field_types:
            raise ValueError(f"Unknown field {key!r}. Valid: {list(field_types)}")
        setattr(obj, key, _cast(raw_value, field_types[key]))
    return obj

An unrecognised key raises with the list of valid field names rather than failing further down the call stack.

3.2Deriving layer shapes once

Observation

Three parts of the program need the spatial size of every layer: the module that builds the network, the check against the routing limits, and the count of neurons and synapses.

Consequence

The shapes need to be computed once, stored, and read by all three consumers. Doing so also makes the geometry testable without a GPU, since the computation is ordinary arithmetic.

In code

plan_network() returns a NetPlan listing every convolution block and linear layer with its input size, output size, channel counts and effective stride. The model builder, check_feasibility and count_neurons_and_synapses all take that object as their input.

The per-layer size comes from the standard convolution formula:

out = ⌊( in + 2·padding − dilation·(kernel − 1) − 1 ) / stride⌋ + 1 A 64×64 map through a kernel of 7 at stride 2 with no padding gives ⌊(64 − 7 − 1)/2⌋ + 1 = 29×29. The floor discards positions where the kernel would not fit.

plan_encoder() applies three rules while walking the stack:

  1. Stop shrinking small maps If a feature map has reached 3×3 or smaller, the layer is forced to stride 1 with size-preserving padding whatever the configuration requested. A kernel larger than the remaining map raises InfeasibleConfig with the sizes involved.
  2. Resolve where downsampling comes from A per-layer pool flag takes precedence and produces a stride-1 convolution followed by pooling. Otherwise the global mode decides between a strided convolution and a pooling layer.
  3. Record the result Each block stores its input size, its post-convolution size, which is where the neurons sit, and its post-pooling size, which feeds the next block.

3.3Three different measures of size

Asking how large a network is has three answers here, and they differ by orders of magnitude. For a convolution with kernel k, Cin input channels, Cout output channels and an H×W output map:

MeasureFormulaMeaning
neuronsCout · H · W Spiking units, one per output position per channel, counted once rather than per timestep.
connectionsneurons · k² · Cin Synapses the chip must route, since each output neuron reads its own window.
parametersk² · Cin · Cout Trainable values in PyTorch. One filter is reused at every position, so this is far smaller than the connection count.

In the two-layer configuration below, the second convolution holds 50,176 parameters and realizes 7.2 million connections, because the same filter is applied at 144 positions. Weight reuse costs a GPU nothing. The chip has to route each connection individually, which is why its limits are expressed as fan-in and fan-out rather than as a parameter budget.

3.5The classifier head

  

    After the convolution stack, a block of shape channels × height × width has to become
    11 class scores. The two available reductions differ in how much fan-in they demand from the
    first linear layer, which section 1.1 limits to 8,159.
  

  

    

      
flatten

      
    
        
  • Unrolls the block into one vector, so 32×12×12 becomes 4,608 features.
    • 
        
  • Every neuron in the following linear layer then has a fan-in of 4,608.
    • 
        
  • Spatial position is preserved, which this dataset rewards. Every strong configuration found by the search used it.
    • 
      

    

    

      
gap

      
    
        
  • Global average pooling reduces each channel to its mean, so 32×12×12 becomes 32 features.
    • 
        
  • Fan-in drops to the channel count, and many more configurations pass the feasibility check.
    • 
        
  • An average is a fixed-weight linear map, so the chip can absorb it into the following layer.
    • 
        
  • Spatial position is discarded, which cost roughly 40 accuracy points on this task.
    • 
      

    

  

  

    Between the reduction and the classifier the configuration may place hidden linear layers. The
    65-trial study described in section 6.6 found that the best configurations used none, so the
    search now allows at most one. Linear layers are built without bias, since the chip provides no
    bias term.
  






  
3.6Uniform and per-layer encoders

  

    EncoderSpec accepts two forms. The uniform form takes a depth, a channel count and
    a kernel size, and repeats them. The per-layer form takes a JSON list of layer dictionaries and
    gives each layer its own geometry, including per-layer neuron overrides.
  

  

    
per-layer encoderemitted by the per-layer search space

    
--encoder layers_json='[
  {"out_channels": 32, "kernel_size": 7, "stride": 2},
  {"out_channels": 64, "kernel_size": 5, "stride": 1, "pool": true},
  {"out_channels": 32, "kernel_size": 5, "stride": 2, "tau": 4, "v_threshold": 0.8}
]'

  

  
    
    
  • When layers_json is present it determines the shape and the uniform fields are ignored.
    • 
    
  • resolve_conv_layers() reduces either form to one list, so the planner, the checker, the cost model and the builder each handle a single representation.
    • 
    
  • Per-layer neuron parameters cost nothing on chip, which reads a neuron model per neuron. Per-channel parameters were considered and rejected as too many degrees of freedom for a dataset of this size.
