The architecture

The tool builds a network from a configuration instead of from code, so a search can try a different network in every trial. This page covers the configuration, how layer sizes are worked out, how big a network is, and which kinds of model the tool supports.

3.1A network written as configuration

A network here is a stack of convolution layers, which find patterns in the image, followed by a head, which turns those patterns into one score per class. If the layer sizes were written into a model class, trying a different network would mean editing code. Writing them as configuration lets the search propose a new network for every trial.

N, C, H, W, T
Batch size, input channels, image height, image width, and the number of timesteps per clip. The batch size groups clips for training and has no effect on the deployed network.
kernel, stride, padding
A convolution slides a small window, the kernel, across the image. The stride is how far the window moves each time; a stride of 2 halves the image size. Padding adds a border so the window can reach the edges.
pooling
A pooling layer shrinks the image by combining neighboring values. Here it averages each 2×2 block.
encoder, head
The encoder is the stack of convolution layers (EncoderSpec). The head maps the encoder's output to class scores (HeadSpec).
flatten, GAP
Two ways to hand the encoder's output to the head. Flatten keeps every position as a separate number. Global average pooling (GAP) averages each channel down to one number.
layers_json
A list of per-layer settings written as JSON. When present, each layer gets its own kernel, channels and downsampling.

The settings are grouped into Python dataclasses, which are plain records of named fields with defaults. Every other module takes these records instead of loose arguments.

DataclassHoldsMain fields
InputSpecthe inputC = 2 polarity channels, H = W = 128, T = 16, resize_to, batch N
ConvLayerSpecone convolutionout_channels, kernel_size, stride, padding, pool, and optional per-layer τ and θ
EncoderSpecthe convolution stackdepth, channels and kernel_size for identical layers, or layers_json; norm
DownsampleSpechow images shrinkstride or pool, pool type and size
HeadSpecthe headflatten or GAP, hidden layer widths, and dropout (silencing random units during training so the network cannot lean on any one of them)
OutputSpecthe classesnum_classes = 11
NeuronSpecthe neuron of page 2τ (a power of two), θ, v_reset, whether τ and θ are learned

Each group can also be set from the command line as key=value pairs. The parser reads the dataclass's own field list, so a new field gets a command-line option without extra code, and an unknown key fails immediately with the list of valid ones.

Example
terminala fully specified configuration
python main.py summary -c configs/dvs128.yaml \
  --encoder depth=2 channels=32 kernel_size=7 stride=2 norm=bn \
  --head    fc_widths= dropout_rate=0.28 \
  --neuron  tau=2

3.2Working out layer sizes once

Three parts of the tool need the size of every layer: the code that builds the network, the check against the chip's limits, and the count of neurons and connections. Computing sizes separately in three places lets them drift apart, which motivates one planner, plan_network(), whose output all three read.

Each layer's output size comes from the standard convolution formula:

out = ⌊( in + 2·padding − (kernel − 1) − 1 ) / stride⌋ + 1

For example, a 64×64 image through a 7×7 kernel at stride 2 with no padding gives ⌊(64 − 7)/2⌋ + 1 = 29, so 29×29.

While walking the stack, the planner applies three rules.

  1. Stop shrinking small images. Once an image is 3×3 or smaller, later layers keep its size instead of shrinking it further. A kernel larger than the image is rejected with the sizes involved.
  2. Decide where shrinking happens. A layer that asks for pooling gets a stride-1 convolution followed by a pool. Otherwise the configuration chooses between a stride-2 convolution and a pool.
  3. Record three sizes per layer. The input size, the size after the convolution (where the neurons sit), and the size after pooling (what the next layer reads).

3.3Four ways to measure size

"How big is this network" has four different answers, because a convolution reuses one small filter at every position of the image. For a layer with a k×k kernel, Cin input channels, Cout output channels and an H×W output:

MeasureFormulaWhat it counts
neuronsCout · H · WSpiking neurons on the chip, one per output position per channel.
connectionsneurons · k² · CinSynapses the chip stores. Every neuron gets its own copy of the filter.
parametersk² · Cin · CoutNumbers that training learns. The filter is shared, so this is far smaller than the connection count.
SynOps (synaptic operations)Σ spikes × fan-outAdditions actually performed on a real clip. Measured, not computed from the shape.

A synaptic operation, or SynOp, is one addition at a neuron caused by an arriving spike. Neuromorphic papers report SynOps per input as a stand-in for energy, so every run measures it. A conventional network of the same shape would do one multiply-add per connection per step regardless of activity, which gives a fair comparison point.

The search can use SynOps four ways when choosing between networks:

ModeWhat it optimizesWhen to use it
accuracyAccuracy only. SynOps are recorded.The default.
constrainedAccuracy, scoring zero above a SynOps budget.When there is a fixed power budget.
weightedaccuracy − weight × SynOps / referenceWhen you can say how much accuracy a halving of SynOps is worth.
paretoBoth, keeping every network that no other network beats on both.When the trade-off is not decided yet.
A worked example

A convolution with 32 input channels, 32 output channels and a 7×7 kernel has 32 × 32 × 7 × 7 = 50,176 parameters. With a 12×12 output it has 32 × 12 × 12 = 4,608 neurons. Each neuron reads its own 7×7×32 window, so the chip stores 4,608 × 1,568 = 7,225,344 connections.

Neither count says how many additions happen during a clip. A neuron that never fires causes none, and one that fires on every step causes one per connection per step. SynOps depend on both the wiring and the input.

3.5The head


After the convolution stack, an output of shape channels × height × width has to become 11 class scores.




flatten
Lays the output out as one long vector, so 32×12×12 becomes 4,608 numbers. Each class neuron connects to all of them, and the network keeps track of where in the image each pattern appeared.


GAP
Averages each channel to one number, so 32×12×12 becomes 32. This cuts the head's parameters from 4,608 per class to 32 and throws away position.




On the chip, GAP does not reduce connections. An average has no neurons of its own, so it is folded into the head's connections, and each class neuron still connects to every neuron of the last convolution layer. Flatten and GAP therefore hit the same fan-in limit. GAP is still worth trying for the smaller parameter count, which can reduce overfitting: learning details of the training clips that do not carry over to new ones.


Between the encoder and the classes the configuration can add one hidden layer of 128, 256 or 512 neurons. When the network deploys its bias through bias neurons (section 4.3), every head layer gets a bias too.






3.6Identical layers or per-layer settings


EncoderSpec accepts two forms. The simple form repeats one depth, channel count and kernel size. The per-layer form takes a JSON list and gives each layer its own kernel, channels, downsampling and, optionally, its own τ and θ.


Example


per-layer encoderemitted by the per-layer search space


--encoder layers_json='[
  {"out_channels": 32, "kernel_size": 7, "stride": 2},
  {"out_channels": 64, "kernel_size": 5, "stride": 1, "pool": true},
  {"out_channels": 32, "kernel_size": 5, "stride": 2, "tau": 4, "v_threshold": 0.8}
]'




When layers_json is present it decides the shape and the simple fields are ignored. One function reduces both forms to the same list, so the planner, the checker, the counts and the builder each handle one representation. Per-layer τ and θ cost nothing on the chip, which stores a neuron model for every neuron.






3.7Which models the tool supports


The goal is a tool that takes any convolutional network and finds a version of it that runs well on HiAER-Spike. Today it builds one family: a sequential stack of convolution layers with a classification head, described by configuration. Changing the dataset, the layer sizes or the neuron settings stays within that family.






You want toSupported todayWhat it would take



Change a convolutional classifierYes: depth, per-layer kernels and channels, pooling or strides, neuron settings, the head, bias neurons.Pick settings the planner can express. The chip check and the simulator check run automatically.


Use another image or event datasetYes: built-in loaders, or your own Python function that returns the datasets.Return the train and test sets with the image size and class count, and pick an input coding (section 5.2).


Load an existing PyTorch modelNo. The builder constructs its own model from configuration.Describe the model as configuration, or add an importer that turns a PyTorch module into the planner's layer list.


Use residual connections, attention or recurrenceNo. The planner and the exporter handle a straight sequence of layers.Extend the planner from a sequence to a graph, decide how branches line up in time (each layer adds one step of delay), and add each operation to the exporter and the simulator.


Do detection, segmentation or regressionNo. The head, the loss and the accuracy measure assume classification.Add the task's outputs, loss and metrics.


Target a different chipNo. The neuron, the number formats and the exporter are specific to HiAER-Spike.Replace the limits, the neuron arithmetic and the exporter, and test against that chip's own simulator.







Importing an existing PyTorch model is the most direct step toward "any CNN". A model that uses an operation the chip cannot run (max pooling, for example) would first need that operation replaced, and the result trained again.
