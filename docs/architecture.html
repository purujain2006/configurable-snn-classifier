The architecture

The tool builds a network from a list of settings instead of from code, so a search can try a different network in every trial. This page covers how layer sizes are worked out, four ways to measure how big a network is, a builder that shows every layer's cost, and which kinds of model the tool supports.

3.1A network written as settings

A network here is a stack of convolution layers, which find patterns in the image, followed by a head, which turns those patterns into one score per class. Page A explains each of those pieces. If the layer sizes were written into the program, trying a different network would mean editing code. Writing them as settings lets the search propose a new network for every trial, and lets the chip check read a network's shape before anything is built.

A few symbols come up on this page.

N, C, H, W, T
Batch size, input channels, image height, image width, and the number of timesteps per clip. The batch size groups clips for training and has no effect on the deployed network.
kernel, stride, padding
A convolution slides a small window, the kernel, across the image. The stride is how far the window moves each time; a stride of 2 halves the image size. Padding adds a border so the window can reach the edges.
flatten, GAP
Two ways to hand the last layer's maps to the head. Flatten keeps every position as a separate number. Global average pooling (GAP) averages each channel down to one number.

Every layer can have its own kernel, channel count and way of shrinking the map, and optionally its own τ and θ. Per-layer τ and θ cost nothing on the chip, which stores a neuron model for every neuron. A network can also repeat one kernel and channel count at every layer, which is the shorter way to write a simple stack. Both forms reduce to the same list of layers, so everything that reads a network handles one representation.

3.2Working out layer sizes once

Three parts of the tool need the size of every layer: the step that builds the network, the check against the chip's limits, and the count of neurons and connections. Computing sizes separately in three places lets them drift apart, which motivates one planner whose output all three read.

Each layer's output size comes from the standard convolution formula:

out = ⌊( in + 2·padding − (kernel − 1) − 1 ) / stride⌋ + 1

For example, a 64×64 image through a 7×7 kernel at stride 2 with no padding gives ⌊(64 − 7)/2⌋ + 1 = 29, so 29×29.

While walking the stack, the planner applies three rules.

  1. Stop shrinking small images. Once an image is 3×3 or smaller, later layers keep its size instead of shrinking it further. A kernel larger than the image is rejected with the sizes involved.
  2. Decide where shrinking happens. A layer that asks for pooling gets a stride-1 convolution followed by a pool. Otherwise the settings choose between a stride-2 convolution and a pool.
  3. Record three sizes per layer. The input size, the size after the convolution (where the neurons sit), and the size after pooling (what the next layer reads).

The third rule matters for the chip. An average pool has no neurons of its own, so the chip check needs the size before the pool, where the neurons are, and the size after it, which sets how the next layer is wired (section 4.1).

3.3Four ways to measure size

"How big is this network" has four different answers, because a convolution reuses one small filter at every position of the image. For a layer with a k×k kernel, Cin input channels, Cout output channels and an H×W output:

MeasureFormulaWhat it counts
neuronsCout · H · WSpiking neurons on the chip, one per output position per channel.
connectionsneurons · k² · CinSynapses the chip stores. Every neuron gets its own copy of the filter.
parametersk² · Cin · CoutNumbers that training learns. The filter is shared, so this is far smaller than the connection count.
SynOps (synaptic operations)Σ spikes × fan-outAdditions actually performed on a real clip. Measured, since it depends on the input as well as the shape.

A synaptic operation, or SynOp, is one addition at a neuron caused by an arriving spike. Neuromorphic papers report SynOps per input as a stand-in for energy, so every run measures it. A conventional network of the same shape would do one multiply-add per connection per step regardless of activity, which gives a fair comparison point.

The search can use SynOps four ways when choosing between networks:

ModeWhat it optimizesWhen to use it
accuracyAccuracy only. SynOps are recorded.The default.
constrainedAccuracy, scoring zero above a SynOps budget.When there is a fixed power budget.
weightedaccuracy − weight × SynOps / referenceWhen you can say how much accuracy a halving of SynOps is worth.
paretoBoth, keeping every network that no other network beats on both.When the trade-off is not decided yet.
A worked example

A convolution with 32 input channels, 32 output channels and a 7×7 kernel has 32 × 32 × 7 × 7 = 50,176 parameters. With a 12×12 output it has 32 × 12 × 12 = 4,608 neurons. Each neuron reads its own 7×7×32 window, so the chip stores 4,608 × 1,568 = 7,225,344 connections.

Neither count says how many additions happen during a clip. A neuron that never fires causes none, and one that fires on every step causes one per connection per step. SynOps depend on both the wiring and the input.

3.5The head on the chip

After the convolution stack, an output of shape channels × height × width has to become 11 class scores. Flatten turns 32×12×12 into 4,608 numbers and connects each class neuron to all of them. GAP turns it into 32, which cuts the head's parameters from 4,608 per class to 32 and throws away position.

On the chip, GAP does not reduce connections. An average has no neurons of its own, so it is folded into the head's connections, and each class neuron still connects to every neuron of the last convolution layer. Flatten and GAP therefore hit the same fan-in limit. GAP is still worth trying for the smaller parameter count, which can reduce overfitting: learning details of the training clips that do not carry over to new ones.

Between the last convolution and the classes the settings can add one hidden layer of 128, 256 or 512 neurons, with dropout (silencing random units during training so the network cannot lean on any one of them) on its input. When the network deploys its bias through bias neurons (section 4.3), every head layer gets a bias too.

3.6Which models the tool supports

The goal is a tool that takes any convolutional network and finds a version of it that runs well on HiAER-Spike. Today it builds one family: a sequential stack of convolution layers with a classification head, described by settings. Changing the dataset, the layer sizes or the neuron settings stays within that family.

Change a convolutional classifierYes: depth, per-layer kernels and channels, pooling or strides, neuron settings, the head, bias neurons.Pick settings the planner can express. The chip check and the simulator check run automatically.

Importing an existing PyTorch model is the most direct step toward "any CNN". A model that uses an operation the chip cannot run, such as multiplying two activations together, would first need that operation replaced, and the result trained again.
