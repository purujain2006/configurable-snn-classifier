Chapter 3 · Architecture & Configuration

A network you describe,
not hard-code

Most research code hard-wires its network. This file treats the entire architecture as data: config → plan → network → exact bill of materials. This chapter walks that chain, then hands you the builder.

3.1Seven dataclasses describe everything

A dataclass = a named bundle of typed, defaulted fields. Seven of them — one per concern — are the complete genome of an experiment:

DataclassOwnsExample fields (defaults)
InputSpecWhat goes inC=2 polarity channels, H=W=128 sensor size, T=16 timesteps, resize_to=0 (0 = keep native), batch N=16
ConvLayerSpecOne conv layerout_channels=128, kernel_size=3, stride=2, padding=0, dilation=1, pool=False + optional per-layer tau/v_threshold overrides
EncoderSpecThe conv stackEither uniform (depth=3, channels=128, … — every layer identical) or per-layer via layers_json; plus bias, norm ∈ {none, bn, tdbn}
OutputSpecWhat comes outnum_classes=11 gestures
DownsampleSpecHow maps shrinkmode ∈ {stride, pool}, pool_type ∈ {avg, max}, pool kernel/stride = 2
HeadSpecThe classifierfinal_reduction ∈ {flatten, gap}, fc_widths="512" (comma list; "" = none), dropout_rate=0.5
NeuronSpecThe neuron (ch. 2)neuron_type="LIF", tau=2 (integer!), v_threshold=1.0, trainable_tau/threshold=False
  • An eighth, TrainSpec, holds the optimization recipe — "everything that affects training but not shape" (optimizer, lr, scheduler, epochs, the QAT knobs from chapter 4).
  • Shape-things vs. training-things stay separate — so the feasibility checker never needs to care how you'll train.

Setting fields from the command line

  • Each group gets a CLI flag taking key=value pairs.
  • One generic function, fill_from_kv, reads the dataclass's own field list for legal keys and type casts.
  • Net effect: adding a config field automatically adds its CLI support — no argparse surgery.

def fill_from_kv(schema_cls, values: list[str]):
    obj = schema_cls()                                    # start from defaults
    field_types = {f.name: f.type for f in fields(schema_cls)}
    aliases = _FIELD_ALIASES.get(schema_cls.__name__, {}) # e.g. old batchnorm=true still works
    for item in values:
        if "=" not in item:
            raise ValueError(f"Expected key=value (e.g. 'N=16'), got: {item!r}")
        key, raw_value = item.split("=", 1)
        if key in aliases:
            key, raw_value = aliases[key](raw_value)
        if key not in field_types:
            raise ValueError(f"Unknown field {key!r}. Valid: {list(field_types)}")
        setattr(obj, key, _cast(raw_value, field_types[key]))
    return obj

Note the error messages: a typo'd key doesn't crash cryptically — it lists the valid field names. This file consistently spends effort on failing legibly.

3.2Shape planning: the network on paper, one source of truth

Before any real network is built, plan_network() walks the whole architecture arithmetically: what does each layer receive and emit? The core formula:

out = ⌊( in + 2·padding − dilation·(kernel − 1) − 1 ) / stride⌋ + 1 A 64×64 map through a k=7, s=2, p=0 conv → ⌊(64 − 7 + 0 − 1)/2⌋ + 1 = 29×29. Fractions are floored: pixels that don't fit a full kernel placement are dropped.

Around that formula, plan_encoder() makes three quietly important decisions per layer:

  1. "Still big enough to shrink?" If the map is already ≤ 3×3, the layer is forced to stride 1 with size-preserving padding — no matter what the config asked for. This guard stops a deep config from grinding the image to nothing (and if the kernel outright exceeds the map, planning raises InfeasibleConfig with a precise message).
  2. Where does downsampling come from? Priority order: a per-layer pool=True flag wins (stride-1 conv, then a pooling layer); else global mode="stride" uses the layer's conv stride; else (global pool mode) stride-1 conv + pool. One rule, applied identically everywhere.
  3. Record everything. Each layer's plan stores input size, post-conv size (where the LIF neurons live), post-pool size, channels, and effective stride/padding — a ConvBlockPlan.
📐
Why "one source of truth" is a headline feature
  • The model builder, the feasibility checker, and the cost model all read this same plan object.
  • The scar tissue behind the rule: previously the model and checker each re-derived shapes with duplicated loops — "which is exactly how the head came to be unchecked." Infeasible networks sailed through.
  • Duplicate a computation and the copies will drift. Compute it once and disagreement is impossible.

3.4The head: flatten vs. GAP, and why it matters so much

  

    After the conv stack, a 3-D block of spiking activity (channels × height × width) must
    become 11 class scores. Two strategies, both configurable:
  

  

    

      
flatten keep every pixel

      
    
        
  • Unroll the whole block into one vector: 32×12×12 → 4,608 features.
    • 
        
  • First linear layer then needs 4,608 × width weights — and every neuron in it has fan-in 4,608 (chapter 4 cares a lot).
    • 
        
  • Preserves where activity happened. This gesture task rewards that: every top model used flatten.
    • 
      

    

    

      
gap average each channel

      
    
        
  • Global Average Pooling collapses each channel's map to its mean: 32×12×12 → 32 numbers.
    • 
        
  • Far fewer params · less overfitting · tiny fan-in (many more configs pass feasibility).
    • 
        
  • Deployable on-chip: an average is just a fixed-weight linear map.
    • 
        
  • The cost: discards where, keeps only how much — historically ~40 accuracy points on this task. Kept as an option; not used by winners.
    • 
      

    

  

  
Between reduction and classifier: zero or more hidden FC layers (fc_widths).

  
    
    
  • The winners used none. The 65-trial analysis found conv features already linearly separable, so the search caps hidden FC layers at one.
    • 
    
  • Every linear layer is bias=False — the chip's linear maps carry no bias field.
    • 
    
  • During training: dropout before each linear; and, like every layer here, a spiking neuron after it.
    • 
  






  
3.5The cost model: three different ways to count "size"

  

    "How big is this network?" has three genuinely different answers — the code refuses to
    conflate them. For a conv layer (kernel k, Cin in, Cout out,
    Hout×Wout map):
  

  

    

      
CountFormula (conv layer)What it measuresWho cares

      
        
neuronsCout · Hout · WoutSpiking LIF units — one per output pixel per channel. Counted once, not per timestep.The chip's neuron budget; energy (each neuron updates T times per sample)

        
connectionsneurons · (k² · Cin)Physical synapses realized on hardware. Each output neuron listens to a k×k×Cin window.The chip's wiring; this is what "10 million synapses" means

        
paramsk² · Cin · Cout (+Cout if bias)Trainable floats in PyTorch. Far smaller than connections because of weight sharing: one k×k filter is reused at every image position.Training, memory, overfitting risk

      
    

  

  
Weight sharing is the punchline:

  
    
    
  • In the depth-2 winner, conv1 has just 50,176 parameters but realizes 7.2 million synapses on chip — one small filter stamped across 144 positions.
    • 
    
  • GPUs exploit the sharing. A neuromorphic chip must physically wire every synapse.
    • 
    
  • Hence the hardware's constraint language — fan-in/fan-out — instead of deep learning's usual "parameter count".
    •

3.6Uniform vs. per-layer: two ways to write the same encoder

  
EncoderSpec accepts two styles:

  
    
    
  • Uniform — depth=3, channels=32, kernel_size=7: every layer a copy. Simple; what the original code did.
    • 
    
  • Per-layer — hand layers_json a JSON list of ConvLayerSpec dicts: each layer gets its own kernels, channels, pooling, even neuron overrides (tau, v_threshold):
    • 
  

  

    
per-layer encoder specwhat the per-layer search emits

    
--encoder layers_json='[
  {"out_channels": 32, "kernel_size": 7, "stride": 2},
  {"out_channels": 64, "kernel_size": 5, "stride": 1, "pool": true},
  {"out_channels": 32, "kernel_size": 5, "stride": 2, "tau": 4, "v_threshold": 0.8}
]'

  

  
    
    
  • When layers_json is present, it wins — uniform fields are ignored for shape.
    • 
    
  • resolve_conv_layers() collapses either style into one canonical list[ConvLayerSpec], so planner, checker, cost model, and builder handle exactly one representation.
    • 
    
  • Per-layer neuron overrides are free on chip (it reads a neuron model per neuron anyway). Per-channel τ/θ were "considered and rejected as too many degrees of freedom for this dataset."
    •
